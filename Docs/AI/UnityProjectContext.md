# Unity project context — Network branch

Baseline: `5af7c8ccaef73a894ba4a2a64c73e113934865db`. Unity 6000.3.11f1.
Current implementation reference: `Network` branch HEAD (structure rework + AI bots).
Read [the detailed Korean handoff](NETWORK_HANDOFF_KO.md) before continuing. The implementation already exists; do not recreate it.
The Network branch initially contained the template SampleScene, Readme scripts, builtin modules and Multiplayer Center; no gameplay or networking implementation.

The template still has URP assets/references, but no URP package in manifest; the new ChessFightLab scene has none. Active Input Handling is Both: the Input System drives movement and the legacy manager is only a compile-time fallback. Do not merge unrelated renderer migrations into networking changes.

Assets are laid out as Materials/, Prefabs/, Resources/, Scenes/, Scripts/ and Settings/, with one script folder per assembly: Scripts/Core (ChessFight.Network.Core, pure C#), Scripts/Network (ChessFight.Network.Steam), Scripts/Game (ChessFight.Game, no Steam reference so prefab scripts always compile), Scripts/Bootstrap (ChessFight.Game.Steam, gated on CHESSFIGHT_STEAM), Scripts/Input and Scripts/Editor (both Assembly-CSharp). The Input System implementation sits in its own ChessFight.Game.Input assembly, gated by versionDefines + defineConstraints on com.unity.inputsystem (the same pattern Steamworks uses), and registers itself so nothing references it directly. Never gate package presence on ENABLE_INPUT_SYSTEM: that define follows the Active Input Handling setting, so it is set even without the package. Unity skips [InitializeOnLoad] in Safe Mode, so the project MUST compile with no optional packages installed or the installer can never run. `Assets/ChessFight/Editor/NetworkSetup.cs` installs Steamworks.NET (pinned git URL) and com.unity.inputsystem (version resolved by the Editor) through the UPM Client API. Keep generated manifest and lock changes together after successful installation.

Architecture: Steam private party lobby (1–6); public match lobby (12); host-owned atomic party reservations; Steam Networking Messages for host-authoritative flat-arena movement. Host departure aborts the match; Steam lobby ownership transfer is not gameplay host migration. No ranked queue or dedicated server.

AI bots are roster entries without a Steam account, added so a small team can test 12-player capacity. Their IDs carry a 0xB tag that cannot collide with SteamID64 plus the owning leader's low bits, so parties cannot forge each other's bots. Bots never join a lobby, are always treated as arrived by the reservation reconciler, are simulated only by the match host, and are never a send or receive target. Generate them only through `BotIdentity`.

`GameBootstrap` attaches itself only in the ChessFightLab scene and reads `GameSceneConfig` for prefabs, materials and UI; only the UI assets fall back to Resources, because their importer-generated file IDs cannot be wired by hand. The template SampleScene is inert and its dead URP components were removed. The arena, pawns and HUD are authored assets instantiated at runtime, because the match roster is only known then. The actual game scene integration must remain explicit.

Tests live outside Assets. `Tools/Test-NetworkCore.ps1` exercises core rules and the production session class with a fake service. `Tools/Test-NetworkCompile.ps1` compiles against real Unity and Steamworks sources. Real Steam, Player builds and visual checks are separate requirements; see `Docs/Network/VALIDATION.md`.
