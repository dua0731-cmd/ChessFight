## 3. 누가 무엇을 정하고 무엇을 보내나

다른 구간과 같은 규칙입니다.
- 판과 씨앗은 매치 번호로 정해서 보내는 것이 없습니다.
- 사람이 바꾸는 것만 방장이 판정해서 구간 상태(`ISectionNetPart`)로 보냅니다.
- 맞음 판정은 방장만 합니다(`ObstacleClock.Authority`).

| 무엇 | 정하는 방법 | 보내는 것 |
|---|---|---|
| 대국 순서 (40경기 중) | 구간 씨앗의 순서(`GiantChessReplay.Game`). 같은 대국은 연달아 나오지 않음 | 없음 |
| 수 · 단계 · 경과 | 대국 시작부터 지난 시간의 순수 함수(`GiantChessReplay.Locate`) | — |
| 대국 시작 시각 | 누군가 체스 방 입구 데크에 처음 닿으면 **방장**이 정함. 판 시작부터 0.1초 단위이고, 방장도 반올림한 값을 씀 | 2바이트 (0 = 아직) |
| 착지 칸 밀어내기 · 충격파 | **방장만**, 자기가 시뮬레이션하는 몸에. 놓친 수를 따라잡을 때는 안 함 | 없음 (폰 위치는 원래 방장 스냅샷) |
| 대국 사이 새 기물 놓기 | 끝난 판에서 새 기물이 놓일 빈 시작 칸이 3초 빨갛게 경고. 놓일 때 그 칸에 선 몸은 방장이 밀어냄 | 없음 |
| 거인 연출 · 표정 | 각 PC가 같은 수 · 단계로 그림. 시선은 각 PC 자기 폰 | 없음 |
| 덮이는 책 | 판 시작부터의 공유 시계로 모든 PC가 같이 덮임. 깔림 판정은 방장 | 깔린 사람 4명까지 × 6바이트 |
| 깔린 모습 | 모든 PC가 그 자리에 납작한 몸을 그리고 진짜 몸은 숨김. 방장은 그 사이 몸을 책의 안전 지점에 붙잡아 둠 | 위 6바이트 (자리 번호 · 책 · 위치 3 · 남은 시간) |
| 타자기 글자 · 힌트 | 구간 씨앗으로 모든 PC가 같음 | 없음 |
| 타자기 키 눌림 · 빨간 키 | 방장 판정 | 3 + 3바이트 |
| 지휘부 문 | 방장이 연 만큼 | 1바이트 |
| 도장 | 원래 공유 시계 + 방장 판정 | 없음 |
| 차원문 막(veil) | 각 PC에서 자기 폰이 지나갈 때만 걷힘 | 없음 |
| 체크포인트 · 늦게 들어온 사람 | 라운드의 자리별 체크포인트 표(CFP6)에 400 ~ 405가 실림 | 기존 표 |

- 대국 순서는 승규 지시대로 "방장 시드"이지만, 씨앗이 매치 번호에서 나와 따로 보내지 않습니다.
- 깔림이 4명을 넘으면 넘은 사람은 납작한 모습 없이 바로 안전 지점으로 갑니다.
- 구간 상태는 모두 33바이트입니다. 판 전체 구간 상태 한도는 96바이트입니다.
- **방장 교체 · 늦게 들어온 사람:** 대국 시작 시각과 깔림 남은 시간이 모든 PC의 상태에 있습니다(HANDOFF 절대 규칙 15).
  - 새 방장은 같은 수에서 이어 갑니다.
  - 늦게 들어온 PC는 상태를 받는 즉시 그 수까지 판을 조용히 다시 놓습니다(밀어내기 · 반응 없음).

### 대국 시계 (방장이 시작 시각을 보낸 뒤 모든 PC가 같음)

- 한 수는 4단계입니다: 쉬기 2 → 날기 3 → 경고 5 → 충격파 0.5 (재생 초).
- 재생 속도가 5라 실제로는 한 수에 약 2.1초입니다.
- 마지막 수 뒤 7초 쉬고 다음 대국으로 넘어갑니다. 그 마지막 3초 동안 새 기물이 놓일 빈칸이 빨갛게 깜빡입니다.
- 오프라인 장면의 Esc는 대국을 멈추고, N은 한 단계를 건너뜁니다. 라운드에서는 둘 다 없습니다.

## 5. 시험하는 법

**혼자 (Unity):**
1. `ChessFight > Pawn Rush > Open Section Test` → Play.
2. 판에 장애물 3이 이 구간으로 나옵니다. `[` `]`로 구간을 옮겨 서재 입구로 갑니다.
3. 볼 것: 문턱 바닥에서 차원문으로 이어지는지, 책 · 도장 · 타자기가 도는지.
4. 체스 방 입구 데크에 서면 대국이 시작하고, 수가 이어지고, 끝나면 다음 대국이 나오는지.
5. 떨어지면 마지막 체크포인트로 돌아오는지.

**두 PC 또는 Steam:**
1. 같은 빌드(프로토콜 v49)로 폰 러쉬 경기를 엽니다.
2. 장애물 3(서재)에서 아래를 봅니다.
   - 두 화면의 대국 · 수가 같은지
   - 참가자도 빨간 칸 · 충격파에 맞는지
   - 책에 깔린 사람이 양쪽 화면에서 납작했다가 같은 안전 지점에 나타나는지
   - 타자기 글자 · 힌트가 같은지, 눌린 키가 참가자 화면에서도 내려가는지
   - 지휘부 문이 같이 열리는지
3. 대국 도중에 한 명이 나갔다 들어오거나 방장이 나가면, 이어서 같은 수가 나오는지 봅니다.

**자동 (사본에서 배치):** `RoyalLibrarySectionValidation.RunPlayBatch`. 결과는 `Logs/RoyalLibrarySection/report.txt`입니다. 사람이 플레이한 것도 온라인도 아닙니다.

## 6. 남은 것 · 주의

- **조명 (R706에 고침):** `RoyalLibraryLighting`은 판 안(`RoyalLibraryMatch` 아래)이면 마차뜰 `YardAtmosphere`와 같은 방식입니다. 카메라가 서재 바깥벽(x ±160, z −151 ~ 171) 안이면 해 · 하늘빛 · 안개 · 보조광 2 · 색 보정이 서재 장면과 같고, 벽 밖 8 m부터 섞이며(0.5초 이징), 0이 되면 판 원래 값을 그대로 되돌립니다. 창 빛 · 빛줄기 · 반사 프로브 · 벽 그림자 끄기는 서재 안 물건이라 늘 있습니다. 서재 장면에서는 늘 1(전과 같음).
  - `RoyalLibraryFlyCam`(F2 비행 카메라)은 라운드 안 서재에서도 켜집니다 — main R706 때 승규 "지금처럼 두기".
- **main (R706):** 장애물 3 자리에 작전 회의실과 함께 후보로 넣었고 프로토콜 v58입니다.
  - main R703의 `SectionRelief`(미니게임을 깬 팀의 앞 구간 완화)는 붙이지 않았습니다(승규 "아직 미정"). 장애물 3 다음은 엔딩이라 지금 규칙으로는 해당이 없습니다.
- 납작한 몸의 이름표는 숨기지 않았습니다.
- 서재 코스 뿌리의 `PhysicsProfile`(120 Hz · 24회)은 라운드 장면 값과 같아서 그대로 뒀습니다.
