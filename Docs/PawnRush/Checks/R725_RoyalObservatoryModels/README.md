## 성능 (`perf.txt`, `perf_views.csv`)

이 노트북(i5-1240P · Iris Xe 내장 그래픽, R719와 같은 PC)에서 1920 × 1080, 게임 카메라 설정 그대로, 20프레임 중앙값.

| | 천문대 | 왕의 서재(R719 기준선, 같은 방식) |
|---|---|---|
| 구간 전체 삼각형 | **3,459,320** (렌더러 375 · 메시 224 · 재질 83 · LOD 0) | 약 110만 |
| 가장 무거운 시점 | 터널 입구 — 화면 안 2,674,294 삼각형, **54.0 ms**(CPU 6.1) | 앞 서재 입구 24.0 ms |
| 가벼운 시점 | 경통 속 — 375,204 삼각형, 21.0 ms | 체스 방 한가운데 18.2 ms |

- 이 PC는 GPU 병목이다(합계의 대부분이 GPU 대기). 터널 입구 54 ms ≈ 18 fps — 서재의 두 배를 넘는다.
- 삼각형의 **55%가 홀 벽(1,897,567)** 이다. 그다음 조각상 205,088 · 대천구 유리 156,588 · 깃발 143,548. 코스 길 쪽 별 단은 하나에 5 ~ 6만.
- LOD가 하나도 없고, 점광원 77개(그림자 없음)가 있다.

## 경량화 뒤 (사용자 "경량화 진행", 목표 "200만")

세 세션이 부품마다 전후 사진으로 사용자 확인을 받고 다시 내보냄(ro-path 별 단 키트 · 기둥 · 레일, ro-hall 대천구 유리 · 달 · 바닥 + 발코니 · 관측대 LOD, ro-shell 홀 벽 칸 · 조각상 · 깃발 LOD0/1/2). 같은 사본 · 같은 방법으로 다시 잼(`perf_after.txt`, 검사 `report_after.txt` PASS). 측정 코드는 LOD 그룹의 단계를 카메라가 고를 단계만 세도록 고침.

| | 전 | 뒤 |
|---|---:|---:|
| 구간 전체(모두 LOD0) | 3,459,320 | **1,910,826** (목표 200만 이하) |
| LOD 그룹 | 0 | 158 (단계별 1,190,428 / 497,601 / 245,595) |
| 홀 벽 | 1,897,567 | 874,530 |

| 손잡이(폰 높이) | 1,697,908 / 28.4 ms | 798,066 / 28.7 ms |
| 국자 | 1,876,986 / 29.9 ms | 948,365 / 30.5 ms |
| 천구 속 | 1,259,329 / 24.8 ms | 685,778 / 23.8 ms |
| 카시오페이아 | 1,219,916 / 24.9 ms | 703,569 / 23.0 ms |
| 경통 속 | 375,204 / 21.0 ms | 310,729 / 23.3 ms |
| 홀 전경 | 2,744,215 / 33.3 ms | 1,104,827 / 30.8 ms |

- 터널 입구는 54 → 38 ms로 줄었지만, 나머지 시점은 삼각형이 절반이 됐는데도 시간이 거의 그대로다(23 ~ 31 ms). 이제는 **삼각형이 아니라 픽셀 쪽 비용**(점광원 77개 · 유리 · 심연 층의 투명 겹침 · 후처리 · 셰이더)이 시간을 정한다고 본다 — 아직 재서 가르지 않은 추정.
- 서재 기준선(같은 노트북)은 18 ~ 24 ms. 천문대는 23 ~ 38 ms.
- 터널 입구의 '가장 나쁜 프레임' 336 ms는 측정 첫 무렵 한 번 튄 것(셰이더 준비로 추정)이고 중앙값과 무관하다.
