# 소드파이트 — 클릭 베기 / 물리 드래그 비교 (R50)

2026-09-27 · `JY-gpt_gamemode`

**사용자 확인:** R48 더미로 혼자 시험 가능. R49는 “물리 시스템 자체는 잘 구현됐지만 타격감과 손맛은 별로”라는 피드백(09-27). **R50 조작 전환·방향·빠른 발도는 사용자 재확인 대기**다. 자동 검사와 손맛 평가는 다르다.

## 실행과 조작

Unity Hub에서 **`C:/Users/trews/.codex/worktrees/jy-gpt-gamemode/ChessFight`**를 연다. 원본 `JY-ragdoll_v2`가 아니다. Play를 정지한 뒤 컴파일을 기다린다.

R50 전체 Windows 빌드도 이 작업 폴더의 **`Builds/SwordFight/ChessFight.exe`**에 갱신했다(Git 제외). Intro→Lobby부터 시작한다. 두 PC는 둘 다 **v9** 빌드가 필요하다. 로컬 커밋 후 원격 푸시는 기존 403 권한 문제 때문에 재시도하지 않으며 GitHub Desktop에서 사용자가 Push한다.

1. Steam 실행 → `Assets/Scenes/Lobby.unity` → Play → **소드 파이트**.
2. **더미 테스트 (혼자 가능) → 적군 + → 테스트 시작**. 매칭 중이면 먼저 취소.
   - 나+더미 1명부터 시작 가능. 아군·적군 ±로 조절하며 팀당 사람+더미 최대 6명.
   - 공개 게임 시작은 여전히 12명 매칭. 방장만 더미 편집 가능; 사람/파티 예약은 보존.
3. 기본은 **물리 드래그**. **좌클릭을 누르고 있기:** 허리의 칼을 조준 방향으로 꺼낸다.
4. **누른 채 마우스를 좌우/상하로 움직이기:** 시점과 함께 칼을 휘두른다. 아래를 보며 베면 낮은 상대를 노린다.
5. **좌클릭 떼기:** 허리에 수납. 발도 여부와 무관하게 시점 감도/회전은 평소와 같다.
6. **F6**, 또는 **Esc → 조작 전환 버튼**: **이전 클릭 베기 ↔ 물리 드래그**. 하단 안내에 현재 방식이 표시된다. 전환 후 마우스를 놓고 새로 누른다. 클릭 베기는 **한 번 클릭하면 정해진 궤도로 한 번 베기**, 누르고만 있어서는 반복하지 않는다.
7. 선택은 각 플레이어별이며 죽고 부활해도 유지한다. 경기 재입장은 물리 드래그 기본값으로 시작. WASD·Shift·Space는 기존 이동·질주·점프. 폰 우클릭 스킬은 없음. Esc 메뉴/로비 복귀.

Steam 없이 `Assets/Scenes/SwordFight.unity`를 직접 Play하면 나+아군 정지 더미1+적 정지 더미2. 메뉴 `ChessFight → Sword Fight → Open Test Scene`도 가능.

## R50에서 바꾼 것

- R48의 클릭 베기 **0.16초 준비 + 0.20초 타격 + 0.34초 회복**, 궤도와 밀치는 힘을 별도 코드로 복원했다. 물리 드래그와 언제든 비교 가능하며 기존 방식이 삭제되지 않는다.
- 물리 칼의 **최대 55도 위쪽 보정**을 없앴다. 검날이 카메라 방향을 따라간다. 바닥/벽이 막으면 실제 물리 접촉이 우선하므로 항상 정확히 일치하는 것은 아니다.
- 초기 발도 공격 대기 **0.25 → 0.05초**. 손목 회전 응답·회전 속도 추종을 개선했다. 지지된 무게중심을 손잡이 관절에 두어 손을 들 때 검이 뒤집히는 현상을 줄인다. 관성·충돌은 유지한다.
- **45% 감도와 150°/초 제한을 모두 폐기**했다. 게임 카메라 감도에 관여하지 않고, 호스트 입력 방향에도 회전 제한이 없다. 유한한 물리 회전 힘/solver 속도 한계는 시뮬레이션 안정성을 위해 남긴다.
- 전환 시 이전 공격·접촉을 취소하고 새 버튼 입력을 요구한다. 공통 `RagdollPawn`, `LabCamera`, 튜닝, 씬/프리팹은 그대로다.

## 물리 드래그의 기본 규칙 (R49에서 유지)

- 물리 드래그는 **손에 관절로 연결한 Rigidbody 칼**이다. 이전 클릭 베기는 충돌체 없는 칼 표시 + 정해진 공격 궤적 판정이며 두 방식의 타격 방식은 서로 다르다.
- 가만히 꺼내 들거나 걷기만 하는 것은 칼 공격이 아니다. **드래그 의도 + 실제 칼 속도 + 실제 칼이 지난 공간/접촉**을 함께 검사한다.
- 같은 상대의 여러 신체 부위 접촉은 합친다. 다음 타격에는 **0.5초 + 추가 조준 이동 35°**가 필요하다. 이는 접촉 중복 억제용 시험값이며 **누운 적 추가타·협공은 허용**한다. 기상 무적은 없다.
- 바닥 아래로 손목을 억지로 꺾지 않고, 자신과의 칼 충돌은 무시한다. 수납/넘어짐/사망/메뉴 중에는 칼 공격을 끈다.
- 실제 칼 자세를 호스트에서 보내고, 클라이언트는 몸과 같은 보간 시간대에 표시한다. 원격 칼은 시각 전용이며 타격을 자체 판정하지 않는다.
- 공통 `RagdollPawn`, `LabCamera`, 튜닝 에셋, 기존 씬/프리팹은 변경하지 않았다. R50은 카메라 인스턴스 감도 설정도 건드리지 않는다.
- 흰 바닥에 묻히던 조작 안내에 어두운 배경을 붙였다. 전체 아트/타격감 완성 작업은 아니다.

물리 드래그의 “꺼내기”는 **누르는 동안 유지·놓으면 수납**이다. 두 방식은 동시에 공격하지 않고 선택한 하나만 동작한다. 최종 조작 확정이 아니라 비교 실험이다.

## 코드·네트워크

- `RagdollLab/Scripts/SwordFightPawn.cs`: 손 관절/칼 물리·스타일 전환·실제 접촉과 sweep. 콜백은 저장만 하고 다음 FixedUpdate에서 판정한다. `SwordFightPawn.Click.cs`는 이전 클릭 베기를 격리한다.

- `Scripts/Core/SwordFightRules.cs`: 득점/생명당 중복 방지/부활/종료.
- `Scripts/Core/SwordFightProtocol.cs`: **CFS3**, 헤더26 + 폰당40 = 최대506바이트 유지. 생존/발도/클릭 방식 선택·보호/부활·타격 표시·hips 기준 칼 위치/회전. 유한값·범위·회전 길이·중복 ID·불가능한 스타일/발도 조합 검사.
- `RagdollLabSteam/SteamSwordFightLink.cs`: 기존 NetworkRuntime.Session 재사용, 채널33. **Steam 프로토콜 v9**. 두 PC 모두 같은 새 빌드 필요.
- **CFR4 레이아웃은 변경 없음**: 입력27바이트의 shove/shoveHeld/3D aim 사용. **소드파이트 채널에서만 ability2를 클릭 방식 선택의 절대값으로 사용**하며 공통 캐릭터에는 전달하지 않는다. Q키 스킬이 아니다. 매 입력에 선택을 반복하며, 메뉴/포커스 이탈/통신 지연에도 선택은 보존한다. 자세73바이트/폰. 클라이언트는 칼 좌표가 아닌 입력만 보낸다.
- 입력60Hz reliable ordered, 자세/칼30Hz unreliable 전체 상태. 몸/칼 약100ms 보간. 입력0.35초 무응답이면 수납·정지, 호스트 자세12초 무응답이면 경기 나감.
- 클라이언트 자체 칼 예측은 없다. 인터넷 왕복 지연이 있는 조작감은 두 PC에서 별도 확인해야 한다.

## 자동 검사·실기 구분

R50: **Core42·모의 Steam20·실제 Unity DLL 전체 컴파일·참조 경계 검사 통과. 최종 Windows 플레이어 42/0을 1600×900·1280×720에서 각각 통과**(`sword-controls-test-r50e.log`, `r50f.log`; 직전 r50d도 42/0). 메뉴 배치/실제 UI 이벤트, 두 조작의 실제 명중, 공격 중 양방향 전환/새 클릭 요구, 부활/원격 스타일, 벽 접촉·급회전·10회 빠른 발도·12칼을 검사했다. 메뉴 렌더도 AI 확인. 직접 마우스 조작/두 PC/사용자 손맛을 대신하지 않는다.

`sword-controls-full-build-r50.log`: Intro/Lobby 및 활성화된 모든 모드의 Windows 전체 빌드 통과, 작업 폴더로 복사 후 게임 어셈블리 해시 일치 확인.

측정 조건: 120Hz, 허공 기본 시점에서 **발도 0.1초 시점 및 10회 반복 최악 오차 0.0도(소수 1자리 반올림)**, 90°/초 회전 추종 최악 **0.7도**. 12칼 손 연결 최대 오차 **0.001m**, 검끝 최저 **0.081m**. 장애물/다른 자세/네트워크 지연까지 이 수치를 보장하는 것은 아니다.

진단 이력: 첫 **39/2**, 메뉴 표시 타이밍 검사 추가 후 **39/3**, 표시 완료를 기다리도록 고친 뒤 **40/2**. 초기화 시 지정한 무게중심이 실제 발도에서는 검날 중앙으로 되돌아가고 수납 방향도 남는 것을 로그에서 확인했다. **충돌체 활성화 순서·Transform/Rigidbody 시작 자세·자동 무게중심/관성 계산 비활성화**를 수정한 뒤 발도 기준을 완화하지 않고 통과했다([PITFALLS §22](../../Environment/PITFALLS.md#22-빠른-발도-시-물리-칼이-수납-방향으로-돌아감-r50)). R49의 오래 기다린 뒤 정렬 검사만으로는 이 빠른 구간을 잡지 못했다.

R49: **Core41·모의 Steam20·실제 Unity DLL 전체 컴파일·참조 경계 검사 통과.** Windows 플레이어 **32/0, 1280×720·1600×900 각각 통과**(`physical-sword-test-r49h.log`, `r49i.log`). 로비부터 시작하는 전체 빌드도 생성했다. 발도/수납, 실제 드래그 명중, 낮은 추가타, 정지 접촉, 아군/부활 보호, 감도/회전 상한, 호스트 급회전 제한, 원격 표시, 벽 충돌, 초기 발도와 관성 안정화, **10회 연속 수납/발도**, 공통 태클/질주, 더미, 12개 칼 물리를 검사했다. 이는 직접 마우스 조작이나 두 Steam 계정 시험을 대신하지 않는다.

진단 기록: 초기 26/2에서 낮은 베기와 바닥 침범을 수정. 발도 검사는 초기 위/앞 방향과 이후 안정화로 나누었다. **한 번 31/0 뒤 재실행에서 칼이 뒤로 젖혀지는 2개 실패**가 나와, 검날 중앙의 자동 무게중심 대신 손잡이 쪽 무게중심/명시적 회전 관성을 적용하고 반복 시험했다. 몸 전체 튜닝을 바꾸거나 한 번 통과를 완료 근거로 삼지 않는다.

최종 기록: 기본 발도 1.25초 후 목표 각도 오차 **2.3°**, 10회 반복 발도 0.8초 시점 최악 **11.4°**. 12칼 바닥 접촉 검사에서 손 연결 최대 오차 약**0.001m**, 검끝 최저 높이 **0.046m**. 이 특정 테스트 조건의 측정값이지 모든 플레이 상황의 보장값은 아니다.

R48 이력: Core40·모의 Steam20·Windows 플레이어18/0. R47 이력: Core37·모의 Steam16·플레이어14/0. R48 더미 사용 가능은 사용자 확인, 세부 정원/두 PC 항목 전부를 확인한 것으로 확대하지 않는다.

`Tools/Test-NetworkCore.ps1`, `Tools/Test-NetworkCompile.ps1`와 실제 Unity 플레이어로 검사한다. 에디터가 작업 폴더를 열고 있으면 임시 사본을 빌드한다.

```powershell
Unity.exe -batchmode -nographics -projectPath <사본> -executeMethod ChessFight.RagdollLab.Editor.SwordFightBuilder.BuildBatch -swordFightTestBuild
Builds/SwordFight/ChessFight.exe -swordFightTest -screen-fullscreen 0 -screen-width 1280 -screen-height 720 -logFile <로그>
```
