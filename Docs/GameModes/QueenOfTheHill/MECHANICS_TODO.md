# 퀸 오브 더 힐 — 래그돌·게임플레이에 새로 필요한 기능 (개발 목록)

2026-09-26 작성(R33). [DESIGN.md](DESIGN.md)(6차 "하늘 궁전", 기물 재디자인)를 만들려면 **지금 프로젝트에 없는 기능** 목록이다. **다른 채팅에서 바로 개발을 시작**할 수 있게 항목마다 다음을 적었다.
- 무엇을, 왜
- 지금 코드 상태(근거 파일)
- 어디에 만드나(어셈블리 경계)
- 네트워크 영향
- 완료 기준

읽기 전에 루트 [HANDOFF.md](../../../HANDOFF.md) §4 절대 규칙을 읽는다. 특히 규칙 13: `Assets/Scripts`는 래그돌 타입을 모르고, 래그돌은 Steam을 모르고, 캐릭터는 `ICharacterDriver`로만 부른다.

## 0. 먼저 정할 것: 어느 브랜치에서 하나

| 작업 종류 | 위치 | 권장 브랜치 | 이유 |
|---|---|---|---|
| 캐릭터 약속·환경 부품·규칙 | `Assets/Scripts/Gameplay`, `Assets/Scripts/Core` | `JY-lobby` | 로비·게임모드 브랜치 규칙(R18) 안 |

**새 채팅을 시작할 때 사용자에게 "래그돌 쪽 작업을 어느 브랜치에서 할지"를 먼저 확인한다.** 두 브랜치에서 나눠 하면 순서가 중요하다: 약속(인터페이스)을 먼저 `Gameplay`에 넣고, 래그돌이 그것을 구현한다.

**2026-09-26 결정(R34):** 래그돌 쪽 작업은 **`JY-ragdoll_v2`**(사용자가 `JY-lobby`의 `d3d617d`에서 만든 브랜치)에서 한다. M1~M4는 약속과 래그돌을 이 브랜치에서 같이 만들었다.

## 2. 새로 필요한 것 — 우선순위 순

P0 = 이것 없이는 레벨을 시험할 수 없음, P1 = 폰 핵심, P2 = 기물·2단계.

### P0

**M1. 움직이는 발판에 실려 가기** — 레벨 상승의 70%가 탈것이다([DESIGN §3.3 A](DESIGN.md)). **가장 먼저 한다.** *(09-26 구현됨: `IMovingSurface`는 모든 `Obstacle`이 구현, 새 부품 `MovingPlatform` — DECISIONS G7)*
- 지금: 발밑 바닥의 수평 속도만 따라간다. 문제 세 가지.
  1. 키네마틱 Rigidbody를 `MovePosition`으로 움직이면 `GetPointVelocity`가 0일 수 있다.
  2. 위아래로 움직이는 발판(곤돌라, 승강기)은 따라가는지 확인되지 않았다.
  3. 도는 발판(궤도 고리, 톱니) 위에서 몸 방향이 같이 돌지 않는다.
- 만들 것:
  - `Gameplay`에 `IMovingSurface` 인터페이스(`Vector3 PointVelocity(Vector3 worldPoint)`, `Quaternion DeltaRotation`)와 `MovingPlatform` 부품. 키네마틱 Rigidbody를 `FixedUpdate`에서 `ObstacleClock` 시간의 함수로 이동·회전한다(결정 G2).
  - 래그돌은 발밑 바닥이 `IMovingSurface`면 그 속도(수직 포함)와 회전을 이동 앵커에 더한다.
  - **벽에 매달린 상태**도 매달린 면이 움직이면 따라간다.
- 경계: 인터페이스·부품은 `Gameplay`. 래그돌은 `Gameplay`를 참조하므로 인터페이스를 읽을 수 있다.
- 네트워크: 발판은 공유 시계로 모든 PC에서 같다. 래그돌은 방장이 계산한다(랩 방식).
- 완료 기준(RagdollTest에 시험대 추가):
  - 수평 왕복 발판, 승강기(3 m/s로 12 m), 도는 원판(20°/초) 위에서 10초 서 있어도 미끄러지거나 떨어지지 않는다.
  - 승강기 위에서 점프해도 다시 발판에 내린다.
  - 움직이는 벽에 매달려 있어도 떨어지지 않는다.

**M2. 캐릭터 약속 확장(입력)** — 갈고리·종·기물 능력 모두 키가 필요하다. *(09-26 구현됨. `Interact`는 앙파상 0.4초 때문에 "누르고 있기"로 만들었다 — DECISIONS G8)*
- 지금: `CharacterCommand`는 Move·Jump·Shove·Grab뿐이다. 랩의 `PawnInput`에는 `sprint`가 있지만 `RagdollDriver`가 넘기지 않는다.
- 만들 것: `CharacterCommand`에 필드를 추가하고 `RagdollDriver`가 전달한다.
  - `Sprint`(누르는 동안)
  - `Ability`(누른 순간, E)
  - `Ability2`(누른 순간, Q, 퀸·킹용)
  - `Interact`(누른 순간, 종·레버·앙파상)
  - `Aim`(월드 방향, 카메라 조준, 갈고리·돌진 방향)
- 오프라인 입력(`MoveInputSource`, `PlaytestSpawner`)과 네트워크 입력 패킷도 같이 늘린다. **네트워크 패킷을 바꾸면 프로토콜을 올린다**(HANDOFF 규칙 9).
- 완료 기준: RagdollTest에서 각 키를 눌렀을 때 래그돌 쪽에서 값이 들어오는 것을 확인(디버그 표시).

**M3. 맞기 약속(피격)** — 룩 돌진, 비숍 돌조각, 킹 충격파, 퀸 칼이 모두 이것을 쓴다. *(09-26 구현됨. 첫 인자 이름은 `push`, 단위 m/s — DECISIONS G9)*
- 지금: `AddVelocity`, `Knockdown`, `NotifyShoved`가 따로 있다. 스테미나를 깎는 공개 함수는 없다.
- 만들 것: `Gameplay`에 `IHitReceiver`(`ApplyHit(Vector3 impulse, float knockdownSeconds, float staminaDamage, bool dropFromWallOrRide)`). `RagdollDriver`가 구현해 기존 함수로 연결한다.
- 완료 기준(RagdollTest):
  - 서 있는 폰에 `ApplyHit`(6 m/s, 1초)을 주면 날아가 1초 넘어졌다 일어난다.
  - 벽에 매달린 폰에 스테미나 2.5를 깎으면 게이지가 준다. `drop`이면 벽에서 떨어진다.

**M4. 물과 부활** — 물에 빠지면 1단계는 체크포인트로, 2단계는 탈락. *(09-26 구현됨: `WaterZone`은 알리기만, 부활은 `PlaytestSpawner`와 시험대가 한다 — DECISIONS G10)*
- 만들 것:
  - `Gameplay`에 `WaterZone` 트리거(래그돌 어느 부위든 닿으면 `ICharacterDriver` 단위로 한 번 알림).
  - 부활 시 `Teleport`가 **갈고리·밧줄·잡기·매달리기·능력 상태를 모두 풀도록** 보장한다(약속 문서에 이미 "잡은 것을 놓는다"가 있음).
- 완료 기준: 벽에 매달린 채, 무언가를 잡은 채, (M5 뒤) 갈고리에 매달린 채 물에 닿아도 2초 뒤 체크포인트에 멀쩡히 선다.

### P1 (폰 핵심)

**M5. 자유 조준 갈고리 = 2칸 이동** ([DESIGN §4.1](DESIGN.md))
- 규칙: 자기 팀 다리의 부서진 끝에서만 쓴다.
  - 카메라 조준(`Aim`) + `Ability`로 던진다(포물선, 사거리 약 30 m).
  - `HookSurface` 표시가 있는 면에만 박힌다. **다리 높이보다 낮은 곳은 튕긴다.**
  - 박히면 약 6 m/s로 끌려 올라가 도착 지점에 올라선다.
  - 빗나가면 1초 뒤 다시 던질 수 있다.
- 만들 것:
  - `Gameplay`: `HookSurface` 표시 부품, 갈고리 투사체(보이는 밧줄 포함), "던질 수 있는 곳" 영역(`HookStartZone`).
  - 래그돌: **밧줄에 매달려 끌려가는 자세와 이동.** 등반처럼 자세를 직접 배치하는 방식을 권장한다. 이동 앵커를 밧줄 위 목표점으로 옮긴다.
- **앙파상**: 적 갈고리가 박힌 곳 2 m 안에서 `Interact` 0.4초 → 갈고리가 빠지고 매달린 적이 떨어진다. 대상은 끌려 오르는 중 또는 도착 후 1초 안인 적. 폰만 할 수 있다.
- 네트워크:
  - 던지기·박힘·떨어짐은 **방장이 판정**하고, 박힌 지점을 모두에게 보낸다.
  - 랩 스냅샷의 상태 바이트는 8비트를 다 썼다 → **바이트를 늘리고 랩 프로토콜을 올린다.**
- 완료 기준(RagdollTest에 다리와 벽 시험대):
  - 여러 방향으로 던져 각자 다른 곳에 박힌다.
  - 다리보다 낮은 곳은 튕긴다.
  - 20 m를 약 4초에 오른다.
  - 앙파상이 되면 떨어진다.
  - 2인 온라인에서 참가자 화면에도 밧줄과 자세가 맞게 보인다.

**M6. 환경 밧줄·사슬·그네** — 탑 S4 그네, S2·S6 사슬, S8 사슬.
- 지금: 잡기(FixedJoint)는 있지만 **밧줄을 타고 오르거나 그네를 타는 동작은 없다.**
- 만들 것:
  - `Gameplay`: `RopeLine`(두 끝점, 흔들림은 시간의 함수), `ClimbChain`.
  - 래그돌: 우클릭으로 밧줄을 잡으면 매달림 → W/S로 오르내림(스테미나 사용) → 점프로 놓으며 흔들리던 속도를 이어받는다.
  - 먼저 **두꺼운 밧줄 기둥을 지금의 벽 등반으로 오를 수 있는지** 시험한다. 되면 사슬은 그것으로 대신한다.
- 완료 기준: 6 m 밧줄 오르기, 틈 8 m를 그네로 건너기.

**M7. 도약대·스프링 승강기** — L자 도약대(S3), 태엽 스프링(S5).
- 만들 것: `Gameplay`에 `LaunchPad`. 밟으면 `IHitReceiver` 또는 `AddVelocity`로 정해진 속도를 준다(넘어뜨리지 않음).
- 확인할 것: 래그돌 이동 앵커가 위로 튀는 힘을 상쇄하지 않는지. 상쇄하면 래그돌에 "발사 중" 상태가 필요하다(점프와 같은 공중 처리).
- 완료 기준: "위 6 m, 앞 3 m" L자 도약이 매번 ±0.5 m 안에 내린다.

**M8. 종·레버·열리는 길("오픈 파일")** ([DESIGN §3.3 B](DESIGN.md))
- 만들 것:
  - `Gameplay`: `Bell`(폰만 `Interact`로 칠 수 있음, 구간마다 처음 한 번).
  - 열리는 길 부품: 빛의 기둥 승강기 칸, 사슬 사다리, 대각선 레일, 캐슬링 도개교, 스프링 승강기, 빛의 다리. 모두 M1 발판 또는 켜고 끄는 충돌체다.
  - 팀 독점 20초.
  - `Core`에 순수 규칙(`QueenHillRules`: 구간별 개척 팀·시각, 독점 끝 시각, 팀 체크포인트)과 Unity 없는 테스트.
- 네트워크: "한 번만 일어나는 이벤트"라 **방장이 판정해 모두에게 확실히 전해야** 한다. 신뢰 이벤트 채널이 아직 없다([ROADMAP](../../Project/ROADMAP.md)). 우선 **경기 로비 데이터 키**로 대신한다(예: `open_3=white|12.5`, 방장만 씀, 모두 읽음).
- 완료 기준: 오프라인에서 종 → 길이 열림 → 20초 뒤 누구나 사용. 두 PC에서 같은 순간에 열린다.

**M9. 체크포인트(개인 + 팀)** ([DESIGN §3.3 C](DESIGN.md))
- 만들 것: `Gameplay`에 `SectionCheckpoint`(구간 착지 발코니), 규칙은 M8의 `QueenHillRules`에 둔다. 다시 나오는 곳 = max(개인 최고 구간, 팀 개척 최고 구간 − 1).
- 완료 기준: 뒤처진 팀원이 물에 빠지면 선두 한 구간 아래에서 나온다.

**M10. 팀과 같은 편 판정**
- 만들 것: 캐릭터마다 팀 번호(백 0 / 흑 1)를 둔다. `Gameplay`에 `ICharacterTeam` 또는 드라이버 속성을 추가한다.
- 쓰이는 곳: 앙파상(적만), 종 독점, 아군 밀치기 규칙(미정), 피격(아군 제외).
- 네트워크는 명단의 `team`을 그대로 쓴다.

### P2 (기물·2단계)

**M11. 승격(폰 → 기물)과 기물별 성능** ([DESIGN §6.2](DESIGN.md))
- 만들 것:
  - 승격 시 **겉모습(메시)과 성능 묶음**(무게 배율, 이동 배율, 등반 배율, 전력질주 여부, 면역)을 바꾼다.
  - 래그돌 크기는 바꾸지 않는다(물리가 달라짐). 겉모습만 바꾼다.
  - 래그돌의 `RagdollTuning` 값 묶음을 기물마다 두는 방식을 권장한다.
- 네트워크: 기물 종류를 스냅샷에 넣는다.

**M12. 기물 능력**

| 능력 | 필요한 래그돌 동작 |
|---|---|
| 룩 직선 돌진(수평 4방향 + 수직) | 0.6초 예고 표시, 중력 무시 직선 이동(이동 앵커를 정해진 경로로), 몸 통과, 경로의 적에 `ApplyHit` |
| 비숍 호버 + 돌조각 | 5초 떠 있기(중력 끔, 느린 이동), 진짜 물리 돌조각(방장이 생성·계산, 동시 3개), 대각 활공(공중 45° 하강) |
| 나이트 L자 도약 + 밟기 | 정해진 궤적 도약(M7 재사용), 착지 지점 표시, 머리 위 착지 판정 → 대상 **찌그러짐** 상태(M13) |
| 킹 체크!·캐슬링·가호 | 반경 충격파(`ApplyHit` 여러 명), 같은 팀 룩과 위치 교환(`Teleport` 둘), 주변 아군 무게·스테미나 회복 배율 |
| 퀸 칼·돌진·호버·시선 | **물리 칼 휘두르기**(맞은 적 날리기 + 넉다운 중 추가타 = 잡힘), 8방향 돌진, 짧은 호버, 적 윤곽 표시(보기용) |

- 퀸 칼의 물리 칼은 이후 **소드 파이트 모드**와 공유할 수 있게 따로 부품으로 만든다.

**M13. 상태 효과**
- 필요한 것: **찌그러짐**(1.2초 이동·점프·잡기 불가, 매달림 해제), **비틀**(0.4초), 면역 타이머.
- 지금: `hitTimer`(비틀과 비슷), `Knockdown`, 상태 enum(Active·Ragdoll·GettingUp)이 있다. 찌그러짐 같은 "움직이지 못함" 상태를 추가한다.

**M14. 네트워크 동기화 확장(래그돌)**
- 늘릴 것: 위 상태(갈고리·밧줄·탈것·기물 종류·능력·상태 효과)를 스냅샷에 넣는다. 입력 패킷에 M2 필드를 넣는다.
- 랩 프로토콜을 올리고, 경기 씬용 래그돌 동기화 다리를 만든다(지금은 랩 씬에서만 켜짐).
- 12명 대역폭은 30 Hz에서 약 2 Mbit/s(랩 측정)였다. 상태가 늘어난 뒤 다시 잰다.
- 전제 결정: "네트워크 래그돌은 방장이 전부 계산"(랩 방식)을 경기에도 쓸지 → 사용자·준영 님 결정.

## 3. 권장 개발 순서

1. **M2**(약속 확장) → **M1**(탈것) → **M3**(맞기) → **M4**(물·부활). 여기까지 되면 탑의 한 구간을 오프라인으로 만들어 시험할 수 있다.
2. **M5**(갈고리 + 앙파상) → **M8·M9·M10**(종·체크포인트·팀) → **M6·M7**(밧줄·도약대).
3. **M11·M12·M13**(기물) → **M14**(네트워크).
4. 병행: 레벨 빌더(레이아웃 JSON → 구간 모듈 배치), `Core/QueenHillRules` 테스트.

각 단계가 끝나면:
- `Tools/run-tests-linux.sh --compile`을 돌린다.
- RagdollTest나 퀸 오브 더 힐 시험 씬에서 사용자가 확인할 순서를 적는다.
- HANDOFF §8대로 문서를 갱신한다.
