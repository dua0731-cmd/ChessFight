# 기물 스킬을 온라인으로 — R96 조건·계획 → R111 구현

> **R111(10-10) 구현함.** 승규 님: "너가 할 수 있는 최대로 네트워크 지연 히트스톱 등등 해줘 시작해줘". 결정 D-S1~D-S9는 §6의 **추천대로** 했다.
> 무엇을 보내나 → [§8](#8-r111-보내는-것과-칸-지도-프로토콜-v16-cfr7), 화면에 그리는 법 → [§9](#9-r111-화면에-그리는-법), PC 한 대로 시험(Steam 없이) → [§10](#10-r111-pc-한-대-로컬-시험-steam-없이), AI가 확인한 것 → [§11](#11-r111-ai가-pc-한-대에서-확인한-것-10-10), PC 두 대 시험 순서 → [§12](#12-r111-pc-두-대-시험-승규-님-steam), 남은 것 → [§13](#13-r111-남은-것과-한계).
> 폰 러쉬 스킬 시험 씬과 퀸 오브 더 힐 스킬 시험 씬만. 소드 파이트 스킬과 실제 경기 씬은 아직 오프라인. **사람이 Unity·Steam에서 본 것은 아직 없다**(AI가 PC 한 대 로컬 시험으로 봄).
>
> 아래 §0~§7은 R96 제안 그대로다(그때 코드 `823e2c4` 기준). R96 승규 님(10-10): "싱글로 하는 건 이 정도면 되고, 이제 멀티플레이로 하기 위한 조건이나 환경을 어떻게 테스트해 볼까 (Unity 적용 X)". 숫자는 계산값이었다. 실제로 잰 값은 §11.

대상은 래그돌 랩 위에서 도는 기물 스킬이다: 폰 러쉬 스킬(`PawnRush_SkillTest`)과 같은 틀을 쓰는 퀸 오브 더 힐 스킬(`QueenOfTheHill_SkillTest`).
소드 파이트 스킬은 실제 경기 씬 복사본에서 돌고 온라인 연결도 따로(`SteamSwordFightLink`)라서 같은 원칙만 따른다.

관련 문서: 스킬을 만들기 전에 쓴 네트워크 원안 [Skills/DESIGN §10](../Skills/DESIGN.md#10-네트워크-방장-판정)(R70), 이동 동기화 [MOTION](MOTION.md), 방장 이전 [HOST](HOST.md), 기획안 상태 [PLAN_V0.1_STATUS](PLAN_V0.1_STATUS.md).

## 0. 요약

- 지금 스킬은 **혼자서만** 된다. 온라인으로 가려면 세 가지가 필요하다.
  1. **스킬 키가 방장에게 간다.** 패킷이 빠져도 한 번은 꼭 가야 한다.
  2. **스킬 상태와 신호가 모두에게 간다.** 상태는 예고·조준·쿨타임이고, 신호는 맞음·벽 쾅·밧줄 걸림처럼 한 번 일어나는 일이다.
  3. **히트스톱을 화면 연출로 바꾼다.** 지금은 게임 전체를 멈추는데, 각자 화면에서만 멈추게 한다.
- 시험은 싼 것부터 한다.
  - E1: Unity 없는 자동 시험
  - E2: PC 한 대의 "그림자 상대"
  - E3: PC 두 대와 Steam 계정 두 개
  - E4: 12명 부하
  - E5: 실제 인터넷
- **지금 코드 그대로 할 수 있는 시험은 두 가지뿐이다.**
  - E0 계산
  - E3 기본 시험: 스킬 없이 밀치기와 넘어짐만 보고, 핑과 초당 바이트를 적는다(§7).

## 2. 지연 계산 (평균, 실제로 재 봐야 함)

방장 물리는 초당 120번 돌고, 스냅샷은 초당 30번, 입력은 초당 60번 보낸다. 재생 지연은 110 ms다.

**내가 누르고 내 말이 움직이는 게 보이기까지**는 아래 시간을 모두 더한 값이다. 합치면 **0.14초 + 왕복 지연**이다.

| 구간 | 평균 |
|---|---|
| 입력이 보내지기를 기다림 | 8 ms |
| 방장까지 가는 길 | 왕복 지연의 절반 |
| 방장 물리가 다음에 돌기까지 | 4 ms |
| 스냅샷이 보내지기를 기다림 | 17 ms |
| 내 PC로 오는 길 | 왕복 지연의 절반 |
| 재생 지연 | 110 ms |

| 왕복 지연 | 40 ms (국내) | 140 ms (F8 +100) | 240 ms (+200) | 340 ms (+300) |
|---|---|---|---|---|
| 내 말이 움직이는 게 보이기까지 | 0.18초 | 0.28초 | 0.38초 | 0.48초 |

**상대가 내 예고를 보고 움직여, 그 움직임이 방장에 닿기까지**는 0.14초 + 상대의 왕복 지연이다. 예고 시간에서 이만큼이 빠진다.
예고를 몸 자세처럼 0.11초 늦게 그리지 않고 **도착하자마자 그리면** 0.03초 + 상대의 왕복 지연으로 줄어든다.

| 상대가 보고 움직일 수 있는 시간 (상대 왕복 100 ms) | 혼자 | 지금 방식 | 예고를 바로 그리면 |
|---|---|---|---|
| 퀸 예고 0.35초 | 0.35초 | 0.11초 | 0.22초 |
| 룩 잠금 0.3초 (그 전 조준 칸은 길이 제한 없음) | 0.30초 | 0.06초 | 0.17초 |
| 비숍 던짐 0.3초 + 무장 0.5초 | 0.80초 | 0.56초 | 0.67초 |
| 나이트 준비 0.15초 + 비행 1.14초 (말굽 착지 표시) | 1.29초 | 1.05초 | 1.16초 |
| 폰 걸음 | 예고 없음 | — | — |

사람이 반응하는 데 약 0.25초가 걸리므로, 퀸과 룩 잠금은 혼자서도 보고 피하기 어렵다.
온라인에서는 룩은 **조준 칸**을 보고 피하고, 퀸은 **원래 보고 피하기 어려운 스킬**이라는 전제로 손맛을 본다(→ §6 D-S4).
방장 자신은 지연이 0이라 유리하다. 같은 시험을 방장과 참가자 역할을 바꿔 한 번 더 해서 차이를 잰다.

## 7. 순서 (제안)

1. **지금, 코드 없이 할 일.**
   - §6을 결정한다.
   - PC 두 대로 스킬 시험 씬 온라인 기본 시험을 한다: F3 → 테스트 방 만들기 → 방 번호로 참가 → 시작.
   - 스킬 없이 밀치기와 넘어짐이 두 화면에서 같은지 본다.
   - F3 창의 핑과 보내기/받기 KB/s를 적어 §2 계산을 실제 값으로 바꾼다.
2. 동기화 규칙을 Core에 넣고 E1 자동 시험을 만든다. Unity 편집기 없이 코드만으로 된다.

R111에서 2·3을 했고, 4는 "그림자 상대" 대신 같은 PC에서 진짜 참가자 창을 띄우는 로컬 시험(§10)으로 했다.

| 내 누름 | 누르는 순간 예고 단계를 내 화면에 먼저 그린다(폰 러쉬 비숍 클릭은 던짐). 자기 시계로 세고, 방장 상태가 그 단계나 그다음이면 맞은 것으로 본다. 왕복 지연 + 0.25초(0.25~0.8초) 안에 안 오면 되돌린다. 룩에게 교대를 청받았을 때 F는 "예"라서 미리 그리지 않는다 | D-S3 |
| 내 조준 | 내 카메라로 바로 그린다: 폰 러쉬 룩·비숍, 퀸 오브 더 힐 퀸·비숍·나이트(머리 자동 조준은 방장 것) | D-S3 |
| 히트스톱 | 게임 시간을 멈추지 않는다. **그 두 말의 그림만** 각자 화면에서 잠깐 멈춘다(`HoldVisual`). 몸은 계속 가고 놓으면 그림이 따라잡는다. 오프라인은 그대로 | D-S2 |
| 누름 전달 | 누른 횟수로 보낸다. 방장은 물리 한 번에 하나씩, 최대 4개까지 쌓는다. 처음 들은 횟수는 지난 것으로 센다 | D-S7 |
| 왕복 지연 | 스냅샷이 **도착할 때** 내 입력 시각을 빼서 잰다(R111 전에는 그릴 때 재서 재생 지연이 섞였다) | — |
| 방장이 바뀜 | 새 방장이 마지막 상태에서 쿨·진군·기상 보호·호위를 이어받고, 하던 스킬은 쿨로 넘긴다. 밧줄·바리케이드도 이어받는다 | D-S6 |
| 늦게 들어옴 | 깔린 밧줄을 그 상태로 만들어 바로 보여 준다 | C11 |
| 소리 | 퀸 오브 더 힐 효과음은 같은 순간 신호로 나서 참가자 화면에서도 날 것이다. **AI는 소리를 못 들어 확인 안 함** | — |

**F12 = 지연 시뮬레이터**(이 PC가 보내고 받는 래그돌 패킷 모두): 꺼짐 → +100 ms → +200 ms·손실 5% → +300 ms·손실 10%. F3 창에도 버튼이 있다. 이동 모터의 F8과 같은 단계다(§4 (가)).

## 10. R111: PC 한 대 로컬 시험 (Steam 없이)

Steam은 PC 한 대에 계정 하나라서, 같은 PC의 게임 둘을 Steam으로 붙일 수 없다. 그래서 같은 경기를 보통 UDP로 잇는 **로컬 시험**(`LoopbackLabLink`)을 만들었다. 패킷·스킬·재생은 Steam 경기와 똑같고, 방·파티·방장 선정·방장 이전만 없다.

**사람이 하는 법**
1. Unity에서 스킬 시험 씬(폰 러쉬 또는 퀸 오브 더 힐)을 Play → **F3** → **"로컬 시험: 방장"**.
2. 같은 PC에서 같은 씬의 빌드(`ChessFight_PawnRushSkills.exe` 또는 `ChessFight_QueenOfTheHillSkills.exe`)를 켜고 → **F3** → **"로컬 시험: 참가 (이 PC)"**. 창이 둘이라 조작은 누른 창에만 간다.
3. 끄기: F3 → "로컬 시험 끄기". Steam은 씬을 다시 열면 돌아온다.

- 명령줄: `-labLoopback host`, `-labLoopback client [방장 주소]`, `-labLoopbackPort 47611`(기본), `-labTrace`(참가자가 받은 것과 그린 것을 기록에 남김).
- 같은 공유기의 PC 두 대도 된다: 참가 PC에서 `-labLoopback client 192.168.x.x`. 방장 PC의 Windows 방화벽이 UDP 47611을 막으면 허용한다.

**AI가 쓰는 개발 명령** (로컬 시험만, Steam 경기는 무시): 방장이 `LoopbackLabLink.Script(...)`로 시간표를 돌린다.

| 줄 | 뜻 |
|---|---|
| `wait 0.5` | 기다림 |
| `host <명령>` / `client <명령>` / `client2 <명령>` | 이 PC의 말 / 모든 참가자 / 두 번째로 들어온 참가자 |
| `place host x z 보는x 보는z` (`client`, `client2`도) | 방장이 그 말을 옮김 |
| `log 글` | 기록 |

명령: `piece Queen`(기물 요청), `skill`(F), `click`(좌클릭), `rclick 0.2`(우클릭 누르고 있기), `jump`, `move x z 초`, `look 방향 기울기`, `lag 0~3`(F12 단계), `shot 파일`, `burst 접두 장수 간격`(연속 화면 저장), `trace`, `hud`, `report`(지연·스킬 상태 한 줄).
- 기록 줄(`[LabNet 19:04:27.455] ...`)은 벽시계를 써서 같은 PC의 두 창 기록이 ms까지 맞는다.
- 개발 명령 패킷은 지연 시뮬레이터를 건너뛴다(명령이 손실 10%에 빠져 시험이 틀어지던 것, R111).

## 11. R111: AI가 PC 한 대에서 확인한 것 (10-10)

Unity 편집기가 방장, 빌드 1~2개가 참가자인 로컬 시험이다. 참가자 화면을 연속 저장해 프레임마다 봤다. **사람 확인이 아니다.**

**폰 러쉬** (방장 + 참가자 1)

| 스킬 | 참가자 화면에서 본 것 |
|---|---|
| 퀸 | 예고(체스판 칸), 번쩍, 터짐, 잡힌 칸 |
| 룩(참가자가 씀) | 누르고 50 ms 안에 내 조준 칸, 돌진이 방장 말을 맞힘 |
| 비숍 | 밧줄이 보이고 방장 말이 걸려 넘어짐. 히트스톱 4장면은 참가자 화면에서만 |
| 나이트 | 연기, 말굽, 잠금 표시, 찍기 |
| 폰 | 두 걸음, 대각선 넘어뜨림 |
| 룩 → 바리케이드 | 참가자 화면에서 부서져 사라짐, 방장이 다시 솟게 함 |

**퀸 오브 더 힐** (방장 + 참가자 2명: 참가자 1 = 적 팀, 참가자 2 = 방장 편)

| 스킬 | 본 것 |
|---|---|
| 퀸 | 적은 빨간 줄무늬 칸, 아군은 아군 색 칸. 맞음과 넘어짐이 두 참가자 화면에 |
| 룩 교대 | 참가자 2 화면에 요청 고리와 "교대 요청 — F = 수락". F로 수락, 방장 판정 72 ms 안, 날아서 자리 바꿈. 청받은 참가자에 +300 ms·손실 10%를 넣어도 수락과 교대가 보임(누르고 약 0.48초 뒤), 자기 스킬을 잘못 미리 그리지 않음 |
| 나이트 | 방장 말 머리에 잠금 → 도약 → 납작(히트스톱 5장면, 참가자 화면에서만) → 착지. 방장 화면에서도 머리를 밟고 납작 |
| 킹 | 적은 빨간 고리, 아군은 초록 고리. 방장 말에 호위가 켜지고 적 화면에서 2초 동안 초록 윤곽선 |
| 비숍 | 떠오름 → 2발(경고 칸·탄·X 파동) → 방장 말이 맞아 넘어짐(히트스톱 4장면) → 내려옴·착지 |
| 폰 | 웅크림 → 돌진 → 적과 부딪힘(히트스톱 2장면) |

**잰 값**

| 무엇 | 지연 없음 | 지연 넣음 |
|---|---|---|
| 방장 예고 → 참가자 화면 | 62 ms | 103 ms(+200 ms·손실 5%) |
| 방장 퀸 터짐 → 참가자 이펙트 | 90 ms | 221 ms(+200·5%) |
| 참가자 누름 → 방장 | 32 ms | 129 ms(+200·5%) |
| 참가자 누름 10번 | — | +300 ms·손실 10%에서 시작 10/10, 취소 10/10 |
| 재생 지연 | 70 ms | 손실 10%를 넣고 약 10초 뒤 103 ms, 지연을 끄고 약 6초 뒤 70 ms |
| F3 창 왕복 지연 | 8~12 ms(같은 PC) | 116 ms(+100), 319 ms(+300·10%) |

**이 시험에서 찾아 고친 것**
- **맞음 번쩍 셰이더가 빌드에 없음**(`Unlit/Color`): 빌드에서 번쩍이 오류를 내서 그 뒤 이펙트가 안 나오고 신호가 약 1초 막혔다. 편집기에서는 안 보이는 문제라 R111 전 빌드에도 있었다. 같은 부품(`SkillInkKit.FlashBody`)을 쓰는 소드 파이트 빌드도 같은 오류가 났을 것이다(소드 파이트 빌드 기록으로는 확인 안 함). → 세 이펙트 파일에서 `Sprites/Default`로 대신하고, 신호 하나가 오류를 내도 다음 신호는 그린다.
- 내 누름 미리 그리기: 방장 단계 시간을 보여 주던 것을 자기 시계로, 폰 러쉬 비숍 클릭은 던짐 단계로.
- 개발 명령이 지연 시뮬레이터의 손실에 빠짐 → 건너뜀.
- 교대를 청받은 사람의 F를 자기 스킬로 미리 그림 → 안 그림(`0afe27f`).
- 손실 10%에서 "한 장 더"가 1초에 한 번 넘게 켜졌다 꺼짐(한 줄 기준, 1초 평균) → 8% 켜짐·5% 꺼짐, 4초 평균. 시뮬레이션에서 손실 10%는 99% 켜져 있고 2분에 약 1번 바뀜, 3%는 안 켜짐(`27a0735`).
- F3 창 왕복 지연을 그릴 때 재서 재생 지연이 섞임(+300 ms에서 396), 처음 들어온 참가자에게 방장 시계를 되돌려 줘 몇 초짜리 값 → 도착할 때 재고, 입력을 아직 못 들은 사람에게는 0을 보냄(`aef76d3`). 이 값은 내 누름 미리 그리기의 시간에도 쓰인다.
- 편집기 방장이 자기 화면을 연속 저장하는 동안(약 3프레임/초) 신호가 최대 250 ms 늦게 그려졌다. 시험 방법 탓이라 고치지 않는다.

## 13. R111: 남은 것과 한계

- **소드 파이트 스킬 온라인은 없다.** `SteamSwordFightLink`는 자기 패킷을 쓴다. 같은 규칙(누른 횟수, 상태 칸, 순간 신호, 화면만 히트스톱)으로 옮기면 된다.
- 실제 경기 씬(폰 러쉬 코스 등)의 래그돌 온라인(M14)은 없다.
- 방장 이전 중 스킬 이어받기(D-S6)는 Steam에서만 일어나는데 아직 아무도 안 봤다. 로컬 시험에는 방장 이전이 없다.
- 12명 부하(E4)는 안 해 봤다. 스킬 패킷은 참가자마다 1024바이트 안이고, 안 들어간 순간 신호는 다음 패킷으로 간다. 방장의 올림은 스킬 중인 말 수만큼 는다(F3 창 "스킬 KB/s").
- 래그돌 연결에 봇이 없어서 맞는 쪽도 사람이어야 한다.
- 몸 움직임은 미리 그리지 않는다(D-S3 (나)). 내 말의 몸은 여전히 "왕복 지연 + 재생 지연 + 약 30 ms" 뒤에 움직이고, 예고와 조준만 즉시 보인다.
