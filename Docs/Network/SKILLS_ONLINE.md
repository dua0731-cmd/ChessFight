# 기물 스킬을 온라인으로 — 조건과 시험 계획 (R96, 제안)

> 승규 님(10-10): "싱글로 하는 건 이 정도면 되고, 이제 멀티플레이로 하기 위한 조건이나 환경을 어떻게 테스트해 볼까 (Unity 적용 X)".
> 이 문서는 지금 코드(`823e2c4`)를 읽고 계산해서 쓴 **제안**이다. Unity는 고치지 않았다. 숫자는 계산값이라 실제로 재 봐야 한다.
> 구현은 §6의 결정이 난 뒤에 한다.

대상은 래그돌 랩 위에서 도는 기물 스킬이다: 폰 러쉬 스킬(`PawnRush_SkillTest`)과 같은 틀을 쓰는 퀸 오브 더 힐 스킬(`QueenOfTheHill_SkillTest`).
소드 파이트 스킬은 실제 경기 씬 복사본에서 돌고 온라인 연결도 따로(`SteamSwordFightLink`)라서 같은 원칙만 따른다.

관련 문서: 스킬을 만들기 전에 쓴 네트워크 원안 [Skills/DESIGN §10](../Skills/DESIGN.md#10-네트워크-방장-판정)(R70), 이동 동기화 [MOTION](MOTION.md), 방장 이전 [HOST](HOST.md), 기획안 상태 [PLAN_V0.1_STATUS](PLAN_V0.1_STATUS.md).

## 0. 요약

- 지금 스킬은 **혼자서만** 된다. 온라인으로 가려면 세 가지가 필요하다.
  1. **스킬 키가 방장에게 간다.** 패킷이 빠져도 한 번은 꼭 가야 한다.
  2. **스킬 상태와 신호가 모두에게 간다.** 상태는 예고·조준·쿨타임이고, 신호는 맞음·벽 쾅·밧줄 걸림처럼 한 번 일어나는 일이다.
  3. **히트스톱을 화면 연출로 바꾼다.** 지금은 게임 전체를 멈추는데, 각자 화면에서만 멈추게 한다.
- 시험은 싼 것부터 한다.
  - E1: Unity 없는 자동 시험
  - E2: PC 한 대의 "그림자 상대"
  - E3: PC 두 대와 Steam 계정 두 개
  - E4: 12명 부하
  - E5: 실제 인터넷
- **지금 코드 그대로 할 수 있는 시험은 두 가지뿐이다.**
  - E0 계산
  - E3 기본 시험: 스킬 없이 밀치기와 넘어짐만 보고, 핑과 초당 바이트를 적는다(§7).

## 2. 지연 계산 (평균, 실제로 재 봐야 함)

방장 물리는 초당 120번 돌고, 스냅샷은 초당 30번, 입력은 초당 60번 보낸다. 재생 지연은 110 ms다.

**내가 누르고 내 말이 움직이는 게 보이기까지**는 아래 시간을 모두 더한 값이다. 합치면 **0.14초 + 왕복 지연**이다.

| 구간 | 평균 |
|---|---|
| 입력이 보내지기를 기다림 | 8 ms |
| 방장까지 가는 길 | 왕복 지연의 절반 |
| 방장 물리가 다음에 돌기까지 | 4 ms |
| 스냅샷이 보내지기를 기다림 | 17 ms |
| 내 PC로 오는 길 | 왕복 지연의 절반 |
| 재생 지연 | 110 ms |

| 왕복 지연 | 40 ms (국내) | 140 ms (F8 +100) | 240 ms (+200) | 340 ms (+300) |
|---|---|---|---|---|
| 내 말이 움직이는 게 보이기까지 | 0.18초 | 0.28초 | 0.38초 | 0.48초 |

**상대가 내 예고를 보고 움직여, 그 움직임이 방장에 닿기까지**는 0.14초 + 상대의 왕복 지연이다. 예고 시간에서 이만큼이 빠진다.
예고를 몸 자세처럼 0.11초 늦게 그리지 않고 **도착하자마자 그리면** 0.03초 + 상대의 왕복 지연으로 줄어든다.

| 상대가 보고 움직일 수 있는 시간 (상대 왕복 100 ms) | 혼자 | 지금 방식 | 예고를 바로 그리면 |
|---|---|---|---|
| 퀸 예고 0.35초 | 0.35초 | 0.11초 | 0.22초 |
| 룩 잠금 0.3초 (그 전 조준 칸은 길이 제한 없음) | 0.30초 | 0.06초 | 0.17초 |
| 비숍 던짐 0.3초 + 무장 0.5초 | 0.80초 | 0.56초 | 0.67초 |
| 나이트 준비 0.15초 + 비행 1.14초 (말굽 착지 표시) | 1.29초 | 1.05초 | 1.16초 |
| 폰 걸음 | 예고 없음 | — | — |

사람이 반응하는 데 약 0.25초가 걸리므로, 퀸과 룩 잠금은 혼자서도 보고 피하기 어렵다.
온라인에서는 룩은 **조준 칸**을 보고 피하고, 퀸은 **원래 보고 피하기 어려운 스킬**이라는 전제로 손맛을 본다(→ §6 D-S4).
방장 자신은 지연이 0이라 유리하다. 같은 시험을 방장과 참가자 역할을 바꿔 한 번 더 해서 차이를 잰다.

**E1 Unity 없는 자동 시험**
- `Tools/Test-NetworkCore.ps1`로 돈다. 지금 Core 91개와 모의 세션 40개가 여기서 돈다.
- Core의 `LinkSimulator`로 지연과 손실을 넣어 수천 번 돌린다. 같은 시드면 결과도 같다.
- 단, 동기화 규칙(인코딩, 누른 횟수, 신호 번호)을 UnityEngine 없이 `Assets/Scripts/Core`에 둬야 이 시험장에서 돈다. `RagdollNetProtocol`은 Vector3를 써서 여기서는 못 돈다.

**E2 PC 한 대의 "그림자 상대"**
- 방장 화면 옆 작은 창에 상대 화면을 그린다. 방장이 보낸 스냅샷과 신호를 `LinkSimulator`로 늦추고 일부 버린 뒤 다시 받아 인형으로 그리는 방식이다.
- 지금의 자동 시험·녹화 도구에 붙이면 AI가 혼자 프레임별로 확인할 수 있다.
- 이 방법이 필요한 이유: Steam은 PC 한 대에 계정 하나라서, 한 PC에 게임을 둘 띄워 서로 붙일 수 없다.

**E3 PC 두 대 + Steam 계정 두 개**
- 두 화면을 녹화한다.
- 각 PC의 스킬 기록 줄에 방장 시각을 붙여 두 PC 것을 맞대어 비교한다.

**E5 실제 인터넷**
- 다른 집, 휴대폰 테더링, 먼 지역(Steam 릴레이)
- 약한 PC가 방장일 때
- 경기 중 방장을 강제로 끔
- 빈자리로 늦게 들어오기

E3에서 지연을 넣는 방법은 셋 중에서 고른다.

- (가) **F8 시뮬레이터를 래그돌 연결에도 붙인다.** 작은 Unity 코드다. 이미 아는 단계(+100 ms, +200 ms·손실 5%, +300 ms·손실 10%)를 그대로 쓴다. **추천.**
- (나) **Steam 자체의 가짜 지연·손실 설정을 개발 빌드에서 켠다.** `SteamNetworkingUtils`의 FakePacketLag·FakePacketLoss 설정값이다. 우리가 쓰는 `SteamNetworkingMessages`에도 걸리는지는 **확인 필요**.
- (다) **코드 없이 Windows용 지연 도구를 쓴다.** 관리자 권한이 필요하다. Steam 릴레이를 거치는 연결에도 걸리는지는 **확인 필요**.

## 5. PC 두 대 시험 시나리오 (E3)

- **지연 단계:** 없음, +100 ms, +200 ms·손실 5%, +300 ms·손실 10%마다 한 번씩 한다.
- **역할:** A는 스킬을 쓰는 사람, B는 맞는 사람이다. 둘 다 화면을 녹화한다.
- **역할 바꾸기:** 같은 시험을 방장과 참가자 역할을 바꿔 한 번 더 한다.

| 스킬 | A가 할 것 | B 화면에서 볼 것 | 합격 |
|---|---|---|---|
| 공통 | 쿨 2초 시험값으로 F를 50번 | — | 방장 기록에 50번 발동, 두 번 발동은 0 |
| 폰 | B에게 곧게 두 걸음, 대각선으로 한 번 | 밟은 칸, C자 고리, 잡힌 칸이 B가 밀리거나 넘어지는 순간과 맞음 | 두 화면 결과가 같음 |
| 퀸 | B가 1 m, 2.2 m, 3.6 m에 서 있게 하고 사용 | 예고 고리, 넘어짐·밀림·그대로 | 결과가 같음. 예고가 뜨기까지 걸린 시간 기록 |
| 룩 | B 쪽으로 조준 → 좌클릭, 10번 | 빨간 줄무늬 칸을 보고 피하기 | 지연 단계별로 피한 횟수 기록(손맛 판단용) |
| 룩 | 벽과 바리케이드로 돌진 | 성벽 톱니 고리 | 두 화면에서 같은 자리 |
| 비숍 | 길목에 던짐 | 같은 자리에 깔리고 같은 순간 무장. B가 가로질러 달리면 같은 순간 넘어지고 줄이 늘어남. 6초 뒤 함께 사라짐 | 결과가 같음 |
| 나이트 | 도약 → 공중 F로 걷는 B의 머리 찍기, 10번 | 말굽 착지 표시, 빨간 고리 | 성공 횟수. A가 꺾기가 늦게 느껴지는지 |
| 방장 이전 | A(방장)가 밧줄을 깐 뒤 A 게임을 강제로 끔 | B가 방장을 이어받음 | 밧줄이 남은 시간대로 이어짐(또는 결정대로 정리) |
| 늦게 들어옴 | 밧줄이 깔린 뒤 C가 빈자리로 들어옴 | C 화면 | 1초 안에 밧줄이 보임 |

## 7. 순서 (제안)

1. **지금, 코드 없이 할 일.**
   - §6을 결정한다.
   - PC 두 대로 스킬 시험 씬 온라인 기본 시험을 한다: F3 → 테스트 방 만들기 → 방 번호로 참가 → 시작.
   - 스킬 없이 밀치기와 넘어짐이 두 화면에서 같은지 본다.
   - F3 창의 핑과 보내기/받기 KB/s를 적어 §2 계산을 실제 값으로 바꾼다.
2. 동기화 규칙을 Core에 넣고 E1 자동 시험을 만든다. Unity 편집기 없이 코드만으로 된다.
3. 스킬 키, 상태, 신호를 래그돌 연결에 싣고 F8을 래그돌에도 붙인다(Unity).
4. E2 그림자 상대 도구를 만든다. 그러면 AI가 지연 단계마다 상대 화면을 프레임별로 확인한다.
5. E3 → E4 → E5 순서로 사람이 시험한다.
