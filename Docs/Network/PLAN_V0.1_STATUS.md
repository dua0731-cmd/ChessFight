# 네트워크 기획안 v0.1 반영 상태

원문: 승규 님의 「체스파이트 온라인 기획안 v0.1」(2026-09-24, `fef9d42` 기준 작성). 사용자가 공유한 claude.ai 아티팩트 `https://claude.ai/artifact/YAcjFdaTyi8QNbFirKS8fr`에 있다. 저장소에는 원문이 없으니, 원문이 필요하면 사용자에게 요청한다.

검토(R13)와 구현(R14, `01dd655`)의 결과다. **코드·테스트는 끝났고 Unity 확인은 아직이다.**

## 1. 기획안 요지

- **M1~M6(매칭):** 기물 선택(10초, 1·2지망), 같은 방 재대결, 핑 기반 방 검색(120ms 이하 먼저, 30초 뒤 확대), 경기 전 최대 핑 기준 호스트 재지정, Rich Presence 참가, 공개 매치 봇 금지.
- **지연 원칙:** 자기 이동·스킬은 로컬 예측, 남에게 주는 효과는 호스트 판정, 예고(텔레그래프) 시간, 넉백 즉시 이벤트, 150ms 되감기 판정, 래그돌 팔다리는 로컬.
- **호스트 끊김 3단계:** ① 0.5초 경고, 2초 정지(당시 코드는 12초) ② 라운드 무효, 파티 유지 ③ 로비 데이터로 1초마다 상태를 남겨 호스트 이전.
- **플레이어 이탈:** 킹은 20초 유예 후 역할 이전, 나머지는 6대5로 진행하고 재입장. 재입장은 원래 명단 ID만 받는 잠긴 방.
- **변수 표:** 패킷 손실(입력 중복 전송, 점프·스킬을 누른 횟수로) · 버전 불일치(프로토콜 + 빌드 번호) · 호스트 CPU(T2) · 보간 버퍼 · 씬 로딩 동기화(3·2·1, 20초) · 체크포인트 순서 검증 · 왕관 이벤트 번호 · 캐슬링 원자성 · 승격 초기화.
- 기타: 한 번만 일어나는 이벤트용 신뢰 채널, 핑 표시·인위적 지연 토글(T8 전제), 두 브랜치 Steam 코드·Unity 버전 통일, 테스트 T1–T10, 결정 D1–D6, 12주 일정.

## 3. 기획안에 보탠 의견

- 호스트가 봇까지 시뮬레이션하므로 T2(호스트 CPU)는 "사람 12명"과 "봇 포함 12명"을 따로 잰다.
- 스냅샷이 20Hz이므로 보간 버퍼는 50ms의 배수로 잡는다.
- 래그돌을 누가 시뮬레이션할지가 킹러시 네트워크 구조 전체를 정한다. 준영 님 작업과 함께 결정한다.

## 4. 승규 님께 요청할 다음 작업

Unity나 Steam 없이 할 수 있는 **명세와 테스트 설계**를 맡긴다. 결과물은 `Docs/Network/` 아래 마크다운으로 받는다. 외부 AI가 쓴 코드는 이 프로젝트의 함정([PITFALLS](../Environment/PITFALLS.md))에 걸리기 쉬우므로 코드는 맡기지 않는다.

| 순위 | 작업 | 결과물 |
|---|---|---|
| 1 | 두 PC 테스트 진행 ([VALIDATION](VALIDATION.md) 최상단 두 표) | 표에 결과, 핑 수치 캡처 |
| 2 | 한 번만 일어나는 이벤트 목록 명세 (체크포인트, 골인, 넉백, 왕관, 캐슬링, 승격) | 이벤트별 판정 주체, 데이터, 신뢰 전송 여부, 유실·중복 처리, 번호 규칙 |
| 3 | 라운드 흐름 상태 전이표 (대기 → 로딩 동기화 → 진행 → 종료 → 재대결/로비) | 늦은 로딩, 호스트 이탈, 플레이어 이탈 처리 포함 |
