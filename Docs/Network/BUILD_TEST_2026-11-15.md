## 5. 문제 하나씩

### 5-1. 소드 파이트가 끝난 방이 '경기 중'으로 남아 다시 들어가게 됨 — 높음

**사실(로그):**
- 2판: 15:52:33 결과 뒤 로비로 → 6초 뒤 같은 방(…199793)으로 "나갔던 경기로 돌아감". 그때 방은 `playing`, 물리 담당 · 주인이 결과 때와 다른 PC. 이 방에서 15:56:37까지 약 4분을 더 있었고(중간에 한 번 나갔다 다시 돌아감), 마지막에 다시 결과 뒤 로비로.
- 4판: 16:14:46 결과 뒤 로비로 → 9초 뒤 같은 방(…594280)으로 돌아감. 그 뒤 다른 6명도 차례로 "자기 자리로 돌아옴". 약 1분 20초 뒤 다시 결과 뒤 로비로.
- 결과 직전 · 직후에 물리 담당이 바뀌었다(2판: 결과 무렵 물리 담당 PC가 응답을 멈춤 — P2P "App did not respond", 4판: 결과 순간 방 인원 10 → 2, 물리 담당이 두 번 바뀜).
- "돌아감"은 로비의 **경기로 돌아가기** 버튼을 눌러야만 생긴다(`LobbyBootstrap.cs:79` → `SteamSession.Rejoin`). 그 버튼이 나왔다는 것은 로비가 그 방을 "아직 진행 중인 경기"로 봤다는 뜻이다.

**원인 *(추정, 코드 근거)*:**
- 로비가 "돌아갈 경기"로 보는 조건은 방 기록 `phase = playing`이고 `ended ≠ 1`이며 방 주인의 심장 박동(`beat`, 5초마다)이 20초 안에 있는 것(`SteamSession.RejoinMatch`, `SteamSession.cs:2590`). 이 경우 버튼 옆에 "진행 중인 경기가 끝나기 전에는 새 경기를 시작할 수 없어요"가 떠서 **새 매칭도 막힌다**(`LobbyBootstrap.cs:302 ~ 305`).
- `ended`는 **물리 담당 PC**가 결과에 들어갈 때 한 번 적는다(`SwordFightMatch.EnterPhase` Result → `LabNetLink.ReportMatchOver` → `SteamSession.EndMatch`). 방 주인이 아니면 주인이 될 때까지 들고만 있다(`endWanted`, R504).
- 결과 무렵 물리 담당이 바뀌면 새 물리 담당은 `SwordFightMatch.TakeOver`(`SwordFightMatch.cs:160`)에서 `overReported = (마지막 화면이 Result)`로만 표시하고 **`EndMatch`를 부르지 않는다.** 참가자였을 때 결과를 봤으면 그때 `ReportMatchOver`가 이미 돌았지만, 그때는 물리 담당이 아니어서 `EndMatch`가 불리지 않았다(`LabNetLink.cs:122`). 그래서 옛 물리 담당이 `ended`를 적기 전에 나가거나 멈추면 **아무도 `ended`를 적지 않는다.** 방 주인은 계속 `beat`를 찍으므로(`SteamSession.cs:2759`, `MatchEnded`가 아니면) 로비에서는 언제까지나 "진행 중"으로 보인다.
- 두 판 모두 결과 무렵 물리 담당 교체가 있었다는 로그 사실과 맞는다. 다만 Steam 방 기록이 늦게 전해졌을 가능성(로비가 나간 지 6초 만에 낡은 기록을 봤을 가능성)은 로그만으로 지울 수 없다.

**영향:** 끝난 판에 다시 들어가 1 ~ 4분을 버림, 그동안 새 매칭이 막힘, 다시 들어간 방에서 물리 담당이 여러 번 바뀜. 다시 들어간 방에서 스스로 나간 것(2판 15:54:21 "경기에서 나감")은 *(추정)* 탈주로 셌을 수도 있다(`SteamSession.WouldDesert`: 경기 중 · 끝나지 않음 · 그 방에서 결과를 못 봄). 로그에는 탈주 기록 줄이 따로 없다.

**고칠 후보(아직 안 고침):** `TakeOver`가 Result를 이어받으면 `EndMatch`도 부르기 / 참가자도 결과를 보면 물리 담당이 바뀔 때를 대비해 끝을 기억했다가 물리 담당이 되는 순간 적기. 폰 러쉬(`SteamPawnRushLink.cs:869`)도 같은 구멍이 있는지 함께 봐야 한다.

### 5-2. 로딩 화면 흐림 필터 예외 — 중간

**사실:** 4번(판마다 한 번), 처음 15:31:35 직후. 폰 러쉬는 `LoadingScreenView.SyncReveal`, 소드 파이트는 `LoadingScreenView.SyncSword`에서, `style.filter` 설정 → UI Toolkit `CreateBlurFilterFunctionDefinition` → `new Material(null)`. 11-10 빌드 로그(`Player-prev.log`)에는 없다.

**원인 *(추정)*:** 코스 공개(R543 이후) · 소드 기물 선택(R624) 화면이 뒤 배경을 흐리고 회색으로 만들려고 Blur · Grayscale 필터를 쓴다(`LoadingScreenView.Reveal.cs:306`, `LoadingScreenView.SwordPick.cs:553`). 편집기에는 있는 UI Toolkit 내장 흐림 셰이더가 **플레이어 빌드에 들어가지 않아** 셰이더가 null. 편집기 Play에서는 안 보이는 오류다.

**영향 *(추정)*:** 예외가 난 그 프레임은 `Update`의 나머지가 건너뛰어지고, 표시 상태는 이미 켜짐으로 바뀌어 다시 시도하지 않는다 → **빌드에서는 뒤 배경 흐림 · 회색 · 1.05배 확대가 없을 것.** 화면 자체는 이어서 떴다(경기는 정상 시작). 사용자가 빌드 화면에서 뒤 배경이 흐렸는지 확인하면 확정된다.

**고칠 후보:** 그 셰이더를 Always Included Shaders에 넣거나 빌드에서 셰이더가 없으면 필터를 건너뛰기.

### 5-3. 물리 담당을 이어받을 때 kinematic 경고 — 낮음

**사실:** 16:16:12(t 2863.5) "물리 담당 PC의 연결이 끊겨 이 PC가 물리 계산을 이어받았습니다" 바로 다음에 linear · angular 경고가 44쌍. 11-10 빌드 로그에도 같은 모양으로 3묶음 528줄 있었다(그때도 "이 PC가 이어받음" 바로 뒤).

**원인 *(추정)*:** 참가자 화면에서 다른 사람 몸은 kinematic(움직임을 받아 그리기만 함)인데, 이어받는 순간 kinematic을 풀기 전에 속도를 넣는 코드가 돈다. 정확한 줄은 이번에 짚지 않았다(`RagdollPawn` 쪽 속도 설정이 여러 곳).

**영향:** Unity는 그 속도를 무시하므로 이어받는 순간 몸이 한 번 멈칫할 수 있다. 화면 문제가 보였는지는 사용자 확인 필요.
