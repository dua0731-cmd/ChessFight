# UI (HUD)

R47 소드파이트 경기 HUD는 `SwordFightHud.uxml/.uss` + `SwordFightTheme.tss` + `Game/SwordFightHud.cs`다. 기존 `RuntimePanels`(한글·화면 확장)를 사용한다. 점수/시간/조작 안내와 Esc 메뉴의 버튼 두 개이며, Legacy Input 대체 클릭도 제공한다. 게임 규칙·래그돌은 뷰가 참조하지 않는다. 로비 HUD는 변경하지 않았다.

사용자 요구: UI는 UXML(UI Toolkit)로 만든다(R2). 한국어, 화면 전체, 폴가이즈 메인처럼 **우측 하단 큰 시작 버튼**(R7). 클릭이 반드시 되어야 한다(R8, R9). Steam 오버레이 대신 게임 안 친구 초대 UI(R10). **로비는 참고 영상처럼**: 파티 라인업, 모드 카드, 파티 바, 매칭 패널(R19).

## 1. 기술 기반

| 항목 | 내용 |
|---|---|
| 방식 | UI Toolkit 런타임 패널. `RuntimePanels.Create`가 `PanelSettings`를 만들어(또는 `GameSceneConfig`의 것을 써서) `UIDocument`에 붙인다 |
| 테마 | `Resources/NetworkTheme.tss` = `@import url("NetworkHud.uss")` 한 줄. **Unity 기본 테마 없음** → ScrollView·Dropdown 등 복합 컨트롤 금지 |
| 해상도 | 참조 1280×720, ScaleWithScreenSize |
| 폰트 | `RuntimePanels.KoreanFont`: OS 폰트 맑은 고딕 → 나눔고딕 → Noto Sans KR → 굴림 → 돋움 → Arial Unicode MS. 실패하면 LegacyRuntime(한글 없음). Console에 `[ChessFight] HUD 폰트:` 로그 |
| 입력 | Active Input Handling = Old. uGUI·EventSystem 없음. UI Toolkit이 자체 이벤트 시스템으로 받는다 |
| 파일 | `NetworkHud.uxml`(로비), `NetworkHud.uss`(모든 HUD 공용), `IntroHud.uxml`, `MatchHud.uxml`(모드 공용 경기 화면), `ChatHud.uxml`(채팅, 모든 씬 위에 패널 하나, §9) |
| 뷰 코드 | `Game/NetworkHudView.cs`(Steam을 모름, `HudModel`만 받는다). 채우는 쪽은 `Bootstrap/LobbyBootstrap.BuildModel()` |

**UXML의 `name`과 `NetworkHudView`의 `Q<T>(name)`이 계약이다.** 한쪽만 바꾸면 해당 버튼이 조용히 죽는다.

## 2. 클릭이 안 될 때를 대비한 이중 장치

1. **본 경로:** UI Toolkit 포인터 이벤트. Active Input Handling이 Old여야 동작한다(`InputSettingsGuard`).
2. **대체 경로(`NetworkHudView.Update`):** 실제 포인터 이벤트가 한 번도 오지 않으면 `Input.GetMouseButtonDown(0)`과 `panel.Pick`으로 버튼을 직접 누른다. 진짜 이벤트가 한 번이라도 오면 꺼진다. **누른 것은 한 프레임 뒤에 처리한다**(R61): 진짜 이벤트는 이 Update 뒤에 오므로, 그 사이에 진짜 이벤트가 오면 대체 경로는 그 클릭을 버린다. 예전에는 세션의 첫 클릭이 두 경로로 다 눌려, 버튼이 아닌 곳(채팅 칸)을 누르면 다른 버튼(소드 파이트 카드)이 눌렸다. **키 입력은 도와주지 못한다.** 그래서:
   - 번호 칸에는 **붙여넣기** 버튼이 있다. 주요 동작에는 단축키(Enter, F, M, Esc)도 있다.
   - 친구 목록은 검색창이 아니라 **페이지 이동**이다.
   - 타이핑이 필요한 새 UI를 만들지 않는다. (예외: 채팅, [§9](#9-채팅-r61-2026-09-30))
3. **진단 로그:** 1초 뒤 패널 상태를 한 번 출력하고, 첫 포인터 이벤트를 받으면 한 번 기록한다. "버튼이 안 눌리고 로그도 없다"면 입력 백엔드 문제다.

버튼은 `focusable = false`다(키보드 포커스를 뺏어 단축키를 막지 않게). 입력칸 밖을 클릭하면 포커스가 root로 돌아가 단축키가 다시 동작한다. 동적으로 만드는 버튼(친구 행, `+ 친구 초대`, 모드 항목)도 대체 경로 목록에 등록한다.

## 4. 시작 흐름 — 참고 영상대로 바꿈

> **R63 2차(10-03): 공개 매칭 중에는 상단 매칭 패널 대신 입장 화면이 로비를 덮는다**([§11-2](#11-2-승규-님-2차-수정-10-03-unity에서-보고)). 아래 패널은 비공개 방·더미 테스트·파티 대기에만 나온다.

```text
대기   [MODE 카드] [게임 시작]          ← 파티장: 파티 전체로 공개 매칭 시작(FindMatch)
                                          파티원: 비활성, "파티장이 시작하기를 기다리는 중"
  ↓ 게임 시작 / 비공개 방 / 코드로 참가
바쁨   [매칭 중 00:03 · 4/12] [취소]      ← 상단에 매칭 패널: QUICK MATCH · 모드, 6칸 VS 6칸
       (비공개 방 방장) [경기 시작]         방 안이면 방 번호·복사·12명 채우기·봇 비우기
```

- **R7의 단계형(게임 시작 → 파티 생성/빠른 매칭 → …)은 R19에서 참고 영상 흐름으로 바뀌었다**([DECISIONS U7](../Project/DECISIONS.md)). 파티는 항상 존재하므로(1인 파티 자동 생성) "파티 생성" 단계가 필요 없고, 게임 시작 위의 모드 카드가 무엇을 시작하는지 보여 준다.
- 바쁨 = 검색 중 ∨ 경기 방 안 ∨ 파티원이 파티장을 따라가는 중. `session.Busy`를 그대로 쓰지 않는다(1인 파티를 만드는 동안에도 true).
- 매칭 중에는 이름표를 숨긴다(매칭 패널과 겹치지 않게, 영상과 같다).
- (R59) 매칭이 **시작한 경기의 빈자리**를 잡으면 매칭 패널 제목이 "진행 중인 경기에 들어가는 중...", 아래 문구가 "나간 플레이어의 빈자리를 채워요"로 바뀐다(`SteamSession.JoiningLive`). 자리를 받으면 곧바로 로딩 화면 → [SESSION §8](../Network/SESSION.md#8-빈자리-채우기-r59-2026-09-30).
- (R60) 경기에서 **먼저 나온 파티원**: 매칭 패널 "파티원 경기 중" · "파티원들이 경기를 마치기를 기다리는 중", 아래 문구 "먼저 나왔어요 · 혼자 하려면 파티 나가기". 취소 버튼은 숨기고 파티 나가기는 켠다(`WaitingForParty`). **파티장**은 경기 중인 파티원이 있으면 게임 시작·비공개 방·방 번호 참가가 꺼지고 "파티원이 경기를 마치고 돌아오면 시작할 수 있어요"(`PartyStillPlaying`). (R63 3차부터 게임 시작 버튼에는 이유 글씨가 없다 → [§11-3](#11-3-승규-님-3차-수정-10-03))
- 봇이 있는 파티는 **릴리스 빌드**에서 게임 시작이 꺼지고 "봇 포함 시 비공개 방 전용"이 뜬다(M6).
- 단축키: **Enter** 게임 시작, **F** 친구, **M** 모드, **Esc** 창 닫기, 닫을 창이 없으면 설정 창(R64, [§12](#12-설정-창-r64-2026-10-05)). 대체 클릭 경로에서도 키는 동작한다.

## 5. 버튼과 호출

**R48 소드파이트:** `create-test` 문구가 **더미 테스트 (혼자 가능)**로 바뀐다. 비공개 방의 `test-bots` 영역에 아군/적군 `ally-less/more`, `enemy-less/more`와 인원·안내를 표시한다. `Add/RemoveTestBot(team)` 호출은 LobbyBootstrap에서 내 팀을 기준으로 바꾸며, 방장만 조작할 수 있다. 숫자는 전체 팀 더미를 표시하되 `−`는 방에서 추가한 더미만 제거한다(파티 더미가 있으면 설명 표시). `start`는 **테스트 시작**, Enter로도 실행. 공개 매칭과 별도로 나+더미 한 명이면 충분하다. 공통 UI Toolkit 바인딩·대체 클릭 경로를 그대로 쓴다.

| 버튼 | 호출 | 조건 |
|---|---|---|
| 게임 시작 | `FindMatch()` | 한가한 파티장, 모드에 씬 있음, (릴리스) 봇 없음 |
| 비공개 방 | `FindMatch(true)` | 한가한 파티장 |
| 모드 선택 창의 모드 | `SetMode(key)` | 한가한 파티장, 씬 있는 모드. 준비 중 모드는 잠김 |
| 경기 시작 | `StartGame()` | 비공개 방 방장, 2명 이상(봇 포함) |
| 취소 | `Cancel()` | 바쁠 때. 파티는 유지 |
| 파티 나가기 | `LeaveParty()` | 한가할 때. 새 1인 파티 |
| `-` / `+` | `SetPartyBots(n)` | 한가한 파티장 |
| 12명 채우기 / 봇 비우기 | `FillRoomWithBots()` / `ClearRoomBots()` | 방장, 시작 전. 릴리스 빌드는 비공개 방만 |
| 파티 코드 복사 / 방 번호 복사 | 클립보드 | 숫자만 복사(화면에는 4자리씩 띄어 보임) |
| 코드로 참가 창: 붙여넣기 / 파티 참가 / 비공개 방 참가 | 클립보드 / `JoinParty()` / `JoinPrivateMatch()` | 띄어쓰기가 있어도 읽는다 |
| `+ 친구 초대`, 친구 | 친구 카드 열기 | 한가하고 파티가 6명 미만 |
| Steam 다시 연결 | `Retry()` | Steam 초기화 실패 때만 보임 |

## 6. 친구 초대 카드

- `SteamSession.Friends()`가 Steam 친구를 읽어 Core의 `FriendInfo`(Steam 타입 없음)로 준다. 그래서 `Game`이 Steam을 몰라도 그릴 수 있다. **이 분리를 깨지 않는다.**
- 그룹: **이 게임 중 → 온라인 → 자리 비움 → 오프라인**, 그룹 제목에 인원. 이 게임 중인 친구는 상대의 Rich Presence 상태("킹 러시 경기 중", "로비에서 대기 중 · 파티 1/6")가 이름 아래에 보인다(`FriendInfo.Detail`).
- 한 페이지 7명, `온라인`/`전체`, `<` `>`, 새로고침. 열려 있으면 3초마다, 닫혀 있으면 10초마다(상단 `친구 n` 숫자용) 다시 읽는다.
- 이미 내 파티인 친구는 `초대` 대신 "내 파티".
- 행의 `초대` = `SteamMatchmaking.InviteUserToLobby`(오버레이 없음). 받는 쪽은 기존 `GameLobbyJoinRequested_t` 경로. `Steam 오버레이로 초대`는 예비 수단.
- 매칭 중에는 파티가 잠기므로 카드가 자동으로 닫힌다.

## 7. 인트로·경기 HUD

## 9. 채팅 (R61, 2026-09-30)

> **R63(10-03): 색과 자리만 바뀜**([§11](#11-메뉴-디자인-c-그랜드-아레나-수정안-r63-2026-10-03)): 호두나무색 판, 채널 색 파티 초록·팀 하늘·전체 금색, 로비 자리 left 24·bottom 192·폭 430. 동작은 아래 그대로.

승규 님 요청: 채팅창 시안 3개([시안 페이지](https://claude.ai/artifact/9Mm5cfqHu4DAp7B75tKjHu)) 중 **A "기보 로그"**. 보낸 사람은 **Steam 이름**. **로비는 화면 왼쪽**(오른쪽에는 게임 모드 목록과 게임 시작이 있어서), **경기 화면은 오른쪽**. Unity에서 써 본 뒤(2차): **평소에는 숨기고 Tab으로 열기, 열린 동안 Tab으로 파티 → 팀 → 전체, Esc나 닫기 버튼으로 닫기, 모든 경기 화면(킹 러시·소드 파이트·나중의 퀸 오브 더 힐)에.** 메시지가 오가는 방식은 [SESSION §9](../Network/SESSION.md#9-채팅-r61-2026-09-30).

```text
닫힘 (로비 왼쪽 / 경기 오른쪽 아래)            열림 (Tab)
 ┌[파티] 캐슬링  2랭크까지 같이 가자┐ ← 새 줄은  ┌ ■파티 ■팀 2 ■전체        [닫기 Esc] ┐

                                            │  3. 나이트메어  승격 발판 내가 먼저        │
                                            │ [파티│ 파티에 말하기_  Enter 보내기 · Tab 채널] │
                                            └────────────────────────────────┘
                                             (경기 중이면 아래에 "입력 중 · 이동 멈춤")
```

| | 내용 |
|---|---|
| 한 패널, 모든 씬 | `NetworkRuntime`이 들고 있는 `ChatBox` 하나가 자기 UI 패널(정렬 순서 50: 씬 HUD 0 위, 로딩 화면 100 아래)을 그린다. **로비는 왼쪽 아래**(`# 코드로 참가` 위, left 20·bottom 156·폭 380), **경기 씬은 오른쪽 아래**(right 24·bottom 28·폭 440). 모드 씬이 자체 시뮬레이션이어도(소드 파이트) 똑같이 나온다. 인트로·로딩 화면에서는 숨긴다 |
| 닫혀 있을 때 | `Tab 채팅` 표시와 안 읽은 줄 수만. 새 줄은 모든 채널에서 최근 4줄까지 `[팀] 이름 글` 모양으로 떠 있다가 **8초 뒤 2초 동안 흐려져 사라진다** |
| 열기 | **Tab.** 로비는 지난번 채널(처음엔 파티), 경기는 팀(없으면 전체, 파티). 방 번호 입력 창이나 모드 선택 창이 열려 있으면 안 열린다(`ChatBox.Blocker`) |
| 열린 동안 | 파티·팀·전체 탭(쓸 수 없는 채널은 흐림, 다른 탭에 새 줄이 오면 금색 숫자), 기보처럼 **채널마다 줄 번호**, 마우스 휠로 이전 대화. **Tab** 다음 채널(파티 → 팀 → 전체), **Enter** 보내기, **Esc**나 **닫기** 버튼으로 닫기(쓰던 글 지움). 빈 칸에서 Enter도 닫는다 |
| 보낸 뒤 | 로비는 열린 채(이어서 쓰기). **경기는 바로 닫힌다**(곧장 다시 움직이게) |
| 막혔을 때 | 입력 줄 끝에 빨간 글씨 3초("1초에 한 번까지 보낼 수 있어요." 등). 글은 칸에 남는다 |
| 열린 동안 멈추는 것 | 캐릭터 이동(캡슐: `NetworkRuntime`, 소드 파이트: `SwordFightGame.ReadLocalInput`), 로비 단축키(Enter 게임 시작, F, M, Esc), 경기의 Esc 나가기, 소드 파이트의 Esc 메뉴·F6. 모두 `ChatBox.KeysHeld`(열려 있거나 방금 닫힘)를 본다 |

- 색: 파티 민트, 팀 파랑, 전체 흰색, **내 이름 금색**. 알림 줄(들어옴·나감)은 금색 기울임.
- 이름과 글은 **서식 없이** 그린다(`enableRichText = false`). `<size=200>` 같은 글을 쳐도 그대로 보인다. 한 줄 80자, 한글은 음절 사이에서 줄이 바뀔 수 있다.
- 입력 칸이 Enter·Tab·Esc를 스스로 처리하지 않게 막는다(`KeyDownEvent`·`Navigation*Event`를 칸에서 먼저 받아 멈춤). 그러지 않으면 Enter에 칸이 닫혀 다음 Enter가 게임 시작이 됐다(Unity에서 봄). 한국어 입력기가 글자를 조립 중일 때 누른 Enter는 조립이 끝난 다음 프레임에 보낸다.
- 열린 동안 다른 곳을 눌러 포커스를 잃으면(로비 버튼 등) 다음 프레임에 입력 칸이 포커스를 되찾는다. 누른 버튼은 그대로 동작한다.
- 소드 파이트는 마우스가 화면에 잠겨 있어 탭·닫기 버튼은 못 누르고 키(Tab·Enter·Esc)로만 쓴다. 소드 파이트 씬은 UI가 밝게 그려져 반투명 창 뒤 글씨가 비쳐서, 경기 화면의 창은 불투명하다.
- **예외:** §2의 "타이핑이 필요한 새 UI를 만들지 않는다"의 예외다(채팅은 쳐야 한다). 포인터 이벤트가 안 오는 PC(대체 클릭 경로)에서는 채팅을 쓸 수 없다.
- **아직 없음:** 욕설 거르기, 상대 차단. 퀸 오브 더 힐은 로비에서 아직 "준비 중"이라 경기가 열리지 않는다. 연결되면 따로 할 일 없이 채팅이 나온다.

파일: `Game/ChatBox.cs`(화면·키, Steam 모름), `Resources/ChatHud.uxml`(이름 계약: `chat-screen`, `chat`, `chat-*`), 스타일은 `NetworkHud.uss` 맨 아래 "chat" 부분. 연결과 위치: `NetworkRuntime.Awake`(`Connect(Session.Chat, Session.CanChat, Session.Say)`)와 `Update`(`Where`). 로비 막기: `NetworkHudView.Build`의 `ChatBox.Blocker`.

## 11. 메뉴 디자인 C 그랜드 아레나 수정안 (R63, 2026-10-03)

승규 님 요청: 인트로·로비·채팅창·로딩 화면을 결과 화면과 같은 그림체로 다시 그리고, 버튼은 누르는 맛과 입체감, "대기업 수준" UI. 시안 1차(성 마당)와 2차(A 로열 퍼레이드·B 토이 박스·C 그랜드 아레나) 중 **C**를 골라 다섯 가지를 고친 **수정안**([시안 페이지](https://claude.ai/artifact/9D9fDTjGLd5GhSdZLff1C8))을 Unity에 옮겼다. 어두운 경기장에 **단풍나무·호두나무 체스판, 마호가니 테, 놋쇠 선, 따뜻한 조명**. **AI가 이 PC Unity에서 화면을 봄(키·버튼은 안 누름), 사용자 미확인.**

**버튼(`ChunkyButtons`)**: 모서리를 깎은 판이 아래 3~7px 두께의 옆면 위에 서 있다. 마우스를 올리면 2px 떠오르고, 누르면 옆면까지 쑥 들어가고, 떼면 튀어 오르며 번쩍하고 빛줄기 10개와 고리가 퍼진다. 색은 역할: **금색 = 가장 중요한 하나**(게임 시작·경기 시작), **단풍나무 = 확인**(복사·비공개 방 참가), **호두나무 = 보조**, **빨강 = 나가기·취소**. UXML에서 `chunky` + `ch-ivory`/`ch-red`/`ch-wood` + `ch-lg`/`ch-sm`/`ch-xs`. 판은 글자 위에 그려지므로 버튼 글자는 자식 라벨로 옮긴다(나중에 바꾼 `text`도 0.1초 안에 옮겨짐). 대체 클릭 경로(§2)로 눌려도 같은 연출(`ChunkyButtons.Pulse`). **소리는 없다**(Kenney UI Audio는 허락 안 됨).

**그림 재료**: 나무결·체스판·마루·전광판·카드·판 무늬는 전부 코드로 그린 텍스처(`MenuArt`, 시안의 나무결 알고리즘 그대로), 3D 글씨는 표시 글꼴을 화면 밖 카메라로 한 번 찍은 그림(`MenuArt.Caption`), 카드·명단 얼굴은 결과 화면 말을 화면 밖에서 자체 조명으로 찍은 그림(`MenuArt.Portrait`). 왕관·꺾쇠 화살표는 Painter2D(`MenuMarks`). **새 에셋은 글꼴 하나**: `Resources/Fonts/BlackHanSans-Regular.ttf`(SIL OFL 1.1, 라이선스 `BlackHanSans-OFL.txt`, Git LFS). UXML에서 `disp` 클래스가 붙은 글자가 이 글꼴(`RuntimePanels.ApplyDisplay`), 나머지는 맑은 고딕. 승인받은 Jua·Kenney Castle Kit는 아직 안 씀.

**로딩 무대의 함정**: 로딩 화면은 씬이 바뀌는 동안 살아 있어야 해서 무대를 로딩 화면 오브젝트 아래(y = −600)에 두고 자기 카메라로 매 프레임 텍스처에 그린다. 경기 씬의 안개·환경광·해가 무대를 바꾸므로, 그리기 직전에만 경기장 설정으로 바꾸고 씬의 해(directional light)를 잠깐 끄고, 그린 뒤 되돌린다(`LoadingStudio.Render`). 무대 조명은 범위가 짧아 y = 0의 경기 씬에 닿지 않는다.

**모드 이름**: 화면 이름이 **폰 러쉬 · 퀸 오브 더 힐 · 소드 파이트**(`GameModes`의 `Name`·`Tagline`·`Summary`). 키(`kingrush`)와 씬(`KingRush`)은 그대로라 매칭·프로토콜은 안 바뀐다. 결과 화면 기본 모드 글자도 "폰 러쉬".

**없앤 것**: `LoadingBackdrop`(로비를 찍은 배경 두 장)과 `PiecePortraits`(각진 말 그림)는 쓰는 곳이 없어 지웠다. 로비·인트로의 흰 타일 광장(`StageKit.Environment`·`Floor`·`Board`)은 결과 화면만 쓴다. 키 안내 줄(Enter·F·Tab·Esc)은 버튼 안 글자(ENTER)와 채팅 칩(Tab)으로 대신한다.

**3D 장면**(시안의 `worldB`를 그대로 옮김):

- 탁자 체스판(단풍나무·호두나무 칸, 마호가니 테, 놋쇠 선·모서리, 테두리의 금색 a~h·1~8), 위에서 흔들리는 놋쇠 램프(빛과 빛기둥이 갓을 따라간다), 어두운 마루, 따뜻한 갈색 배경과 흔들리는 빛줄기 3개.

**구현 메모**

- 숫자는 시안(three.js) 그대로다. 시안 좌표는 이긴 팀이 +Z라 Unity에서는 Z만 뒤집는다(`PawnRushResultStage.W`). Unity 기본 파이프라인에는 톤 매핑이 없어서 램프·채움 빛 세기와 보드 광택만 화면을 보며 맞췄다.
- 배경: 시안은 투명한 3D 아래에 CSS 배경(위가 밝은 갈색 원형 그라데이션 + 흔들리는 빛줄기)을 깔았다. Unity에서는 카메라 먼 쪽에 붙인 판(`Backdrop`)이 같은 일을 하고, 마루가 닿는 곳은 마루가 가린다. 반사는 씬 기본(파란 하늘) 대신 시안의 갈색 홀 환경을 코드로 만든 큐브맵(`HallReflection`)이다. 처음 판이 파랗게 보이던 원인이 이것이었다.
- 칸 빛·결승 고리·내 고리는 더하는 빛(Standard를 검은 바탕 + 발광, One/One 혼합), 불꽃·먼지는 한 메시에 모은 점(`Dots`), 꽃가루는 인스턴싱. 불꽃의 더하는 빛은 `Legacy Shaders/Particles/Additive`를 쓰고, 빌드에 그 셰이더가 없으면 일반 반투명으로 그린다.
- 결과판: Unity 6.3 Painter2D의 그라데이션 채우기(`fillGradient`)로 CSS의 그라데이션·나무 줄무늬·잘린 모서리(clip-path)를 같은 모양으로 그린다(`PawnRushResultHud.Paint`). 단색 채우기도 알파 키가 있는 그라데이션으로 넣는다(두 색 도우미는 알파를 버린다). 그라데이션 글자(승리!·패배·숫자)는 가로 띠마다 잘라 색을 바꾼 글자를 겹친다. 육각 얼굴은 메뉴의 말 그림(`MenuArt.Portrait`)을 한 번 복사해 팀색 육각으로 자른 텍스처이고, 진 쪽은 색을 뺀 같은 그림을 겹쳐 서서히 바꾼다.
- 시안의 CSS 애니메이션(카드·숫자·고리·빛살)은 결과 시간(`tp`)으로, CSS 전환(결과판 들어옴·숨기기·부제)은 실제 시간으로 돌린다. 그래서 한 순간에 멈춰 둬도 숨기기는 움직인다.
- 숫자 글꼴은 PC에 있는 것(Consolas → Cascadia Mono → Lucida Console)을 이름으로 고른다. 없는 이름으로 만든 OS 글꼴은 UI Toolkit이 아무것도 안 그리거나 다른 글자를 그린다.
- 버튼은 다른 HUD와 같은 대체 클릭(§2).

**미리보기(씬을 혼자 열었을 때):** 예시 경기(`MatchResult.Example`, 백팀이 4:12에 4명째)를 Victory는 백팀 폰돌이, Lose는 흑팀 갬빗으로 본다. **R** 다시 재생, **H** 결과판 숨기기. 버튼과 12초 끝은 이동하지 않고 안내 글만 띄운다. 인스펙터 `preview`, 검토용 `holdAt`(그 초에서 멈춤, 음수면 재생)·`holdHidden`(결과판 숨긴 채), 코드로는 `Hold(초, 숨김)`.

**아직 없음:** 경기 흐름 연결. 결과를 코스 결승 그 자리에서 보여 줄지 따로 씬으로 넘어갈지 미정(승규 님 ④). 연결할 사람은 이긴 팀은 `PawnRushVictory`, 진 팀은 `PawnRushLose`를 열고 `PawnRushResultDirector.Show(MatchResult, 내 팀)`로 결과를 넣은 뒤 `LobbyRequested`(로비로·12초 끝)·`RequeueRequested`(다시 매칭)를 받는다. 무승부 전용 화면(지금은 이긴 쪽 화면처럼 보임), 효과음, 16:9가 아닌 창에서의 배경 맞춤은 아직 안 다듬었다.
