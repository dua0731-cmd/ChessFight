# 체스타이머 씬 직접 멀티플레이 (R114)

2026-10-26. 사용자의 최종 지시대로 **로비 씬을 거치지 않는다**. `ChessTimerMinigame.unity`를 직접 Play하면 기존 래그돌 테스트 씬처럼 Steam 방 생성/코드 참가 패널이 자동으로 붙는다. 기존 로비 메뉴·모드 목록·Build Settings는 변경하지 않았다.

## 두 PC 실행 순서

1. 두 PC에 같은 최신 프로젝트와 기존 Steamworks.NET 패키지가 있어야 한다. 각기 다른 Steam 계정으로 로그인한다. Editor끼리 또는 같은 버전의 Development Build끼리 시험한다(개발/출시 빌드 구분은 기존 정책 유지).
2. 양쪽에서 Unity 메뉴 **ChessFight → Minigames → Open Chess Timer Prototype** → **Play**. 오른쪽 온라인 패널은 **F2**로 열고 닫는다.
3. 한 PC가 **방 만들기 → 방 코드 복사**, 다른 PC가 코드를 입력하고 **방 코드 참가**.
4. 필요하면 방장이 **백팀 봇 추가 / 흑팀 봇 추가**. 팀별 최대6명이며 서로 독립적으로 접속한 두 사람은 기존 예약 정책으로 팀이 배정된다. 사람 한 명+봇도 시험 가능하다.
5. **함께 시작**을 누르면 각 PC가 준비됨을 알리고 공통 시작 시각에 진행한다. 해당 씬에서 그대로 시작하며 다른 씬으로 이동하지 않는다. 사람은 로비/방 명단의 자기 캐릭터만 조작한다.
6. WASD/점프/질주·좌클릭 밀치기·우클릭 잡기·**F 도구 획득/누르고 절단**·H 자기 팀 힌트. Esc는 개인 메뉴이고 전체 경기는 멈추지 않는다.
7. F2 또는 Esc의 **방 나가기**로 연결을 종료한다. 나간 PC는 같은 씬의 오프라인 테스트 상태로 돌아간다. 남은 사람은 기존 방장 이전 절차로 계속 진행한다.

오프라인으로 시험하려면 F2를 닫고 기존 Enter 시작을 사용한다. Steam 초기화 실패 시 패널에 오류와 재연결 버튼이 표시되며 오프라인 기능은 유지한다. Steam 패키지가 없는 환경에서는 네트워크 어셈블리 자체가 제외되어 접속 패널이 생기지 않는다. 현재 PC가 이미 로비의 `NetworkRuntime`을 소유하면 중복 Steam 초기화를 피하기 위해 이 독립 접속기를 붙이지 않는다. **Play를 멈추고 체스타이머 씬에서 직접 시작한다.**

## 공유하는 게임 상태

- 물리/인원수: 방장이 실제 래그돌·잡기·밀치기·발판 접촉을 계산. 적/아군 구분 없이 각 발판에 올라간 플레이어 수를 센다. 비어 있는 슬롯은 비활성화하여 유령 인원이 생기지 않는다.
- 입력: 참가자는 월드 방향 입력과 행동 버튼만 전송. 절단할 전선, 진척도, 타이머, 좌표를 권위 값으로 보내지 않는다. 방장이 위치·접지·기절·도구·거리를 검사한 뒤 전선을 선택하고7초 절단을 진행한다.
- 퍼즐: 방장의 실제 생성 결과(양 팀3단계 기물/전선 위치·종류·폰 방향)를 전송. 클라이언트 임시 판은 첫 스냅샷 전 숨긴다. 단계 전환 때만 메시를 다시 만든다. 동일 전선 다중 작업에 가속이 붙지 않는다.
- 규칙: 제한60초·오답5초·잠금2초, 동시 완료 잔여시간 비교/동률 양 팀 폭발, 기존 문 개방 규칙 유지.
- 연출: 타이머 숫자·발판 기울기·진행 도구·잘린 전선·문·통과 기록·폭발 일련번호/위치·리스폰 남은 시간 공유. 과거 폭발은 처음 입장한 클라이언트에서 다시 재생하지 않는다.
- 봇: 방에 추가한 봇만 방장이 구동. 팀 슬롯2~3번은 기존 상단 대련 배치,4~6번은 기존 절단 지원 역할. 사람을 봇 로직이 대신 조종하지 않는다. 방장 메뉴/포커스와 관계없이 게임 규칙과 봇은 진행한다.
- 온라인에서는 Tab/T 캐릭터 변경, 숫자키 순간 배치, R 복귀, F3 전체 초기화가 비활성이다. 온라인 라운드를 새로 시험하려면 방을 나와 다시 시작한다.

## 구조와 복구

`RagdollLab`은 Steam을 참조하지 않는다. 새 `ChessTimerMinigame.Network.cs`는 역할/입력/상태 적용만 제공한다. `RagdollLabSteam/SteamChessTimerLink.cs`가 기존 `SteamSession`·`RagdollNetProtocol`을 재사용한다. 기존 `SteamRagdollLink`와 같은 **단독 씬 세션 소유 방식**이며 `NetworkRuntime`과 동시에 초기화하지 않는다. 씬 YAML에는 Steam 컴포넌트 참조를 저장하지 않는다.

- 전용 Steam 채널34, 입력60Hz(신뢰/순서 보장), 캐릭터 자세30Hz(비신뢰/약100ms 보간), 규칙/퍼즐 전체 스냅샷10Hz(비신뢰, 다음 패킷으로 복구).
- 기존 입력/자세 패킷 형식은 변경하지 않는다. 새 상태 패킷은 Core의 `ChessTimerProtocol`, magic `CTC1`, 최대4096바이트. 방 ID·송신자·순서·크기·유한 수치·범위·중복 소유자/칸·전선 상태 등을 검사한다. 다른 방/이전 방장/잘못된 상태는 적용하지 않는다.
- 빌드 식별자 `chess-timer-v1/<기존 BuildTag>`로 다른 로비/래그돌 씬과 접속을 분리한다. 공통 SteamSession 프로토콜 및 기존 패킷은 호환 변경이 없어 유지한다.
- 입력이0.35초 이상 오지 않으면 중립 입력/절단 중단. 미수신 상태가 이어지면 기존 SteamSession 방장 선출을 사용하고15초 이상 복구되지 않으면 연결 종료.
- 방장 변경 시 최근 전체 상태의 남은 시간·스위치 안정화·진행 중인 절단/작업자·단계·미래 판 배치·문·폭발/리스폰 기록을 이어받는다. 최신 캐릭터 자세로 물리를 재개한다. **물리 속도와 잡기 관절은 기존 래그돌 인계 방식대로 재설정되므로 짧은 움직임 불연속은 실기 확인 대상**이다. 최근 상태 간격만큼(통상0.1초 전후) 진행이 되돌아갈 수 있다. 복구 상태를 한 번도 받지 못한 PC가 방장이 되면 임의로 새 게임을 시작하지 않고 연결을 종료한다.
- 중도 참가/빈자리 복귀는 기존 SteamSession 허용 조건에 따른다. 받은 전체 상태로 현재 판을 복원한다. 인원 상한이나 진행 중인 방의 자리 예약 정책을 따로 변경하지 않았다.

별도 채팅 UI, 로비 모드 선택, 다음 스테이지 씬 전환은 이번 범위가 아니다.

## 확인 상태

구조26·Core113·모의 Steam 세션40·런타임7개 호환 컴파일 통과(Input/Editor 제외). 새 검사는40개 생성 코스×3단계×양 팀 배치 복원, 중간 절단/스위치 안정화 인계, 오답 잠금/폭발/리스폰/문 복원, 동시 최종 완료, 패킷 잘림/다른 방/잘못된 값/500개 변형, 독립 방 코드 참가/공통 시작/방장 이탈을 포함한다.

**실제 Steam 2PC·Unity/PhysX는 미실행**. 동일 판 표시, 잡기/밀치기, 양쪽 F 동시 절단, 발판 인원, 폭발/문, 포커스 전환, 방장 종료 후 진행 유지, 나갔다 재참가를 위 실행 순서로 확인해야 한다.
