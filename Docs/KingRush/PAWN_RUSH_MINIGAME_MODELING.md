2026-11-05 · R311 · **이미지·모듈 제작 제안 / 사용자 확인 전**

**R312 구현 갱신(2026-11-06): 이 가이드를 바탕으로 실제 Unity 미니게임 구간 프리팹10개를 구워 저장했다.** 초반3종·중반4종·후반3종을 슬롯2·4·6에 등록했다. [현재 자산·여는 법·편집 주의사항](PAWN_RUSH_MINIGAME_SECTIONS.md)을 먼저 확인한다. 아래 R311 이미지와 모듈·LOD 제안은 제작 참고 이력이며 사용자 확정·성능 측정 결과가 아니다.

사용자 요청은 초반 미니게임 3D 디자인을 중반·후반과 같은 방식으로 개편하고, 실제 인게임에 들어갈 공간을 예상한 상세 이미지를 만들어 모델링에 활용하는 것이다. 이미지 범위는 초반·중반·후반 **10종 전체**다. 이 문서는 주변 건축, 기능성 가구, 장식과 동적 부품을 나누어 제작하기 위한 지침이다.

**생성 이미지는 외형·재질·조명의 제안이다. 정확한 치수·개수·좌표를 이미지에서 재지 않는다. 기존 게임 규칙과 아래 치수표, [3D 배치](PAWN_RUSH_MINIGAME_PREFABS.md)를 우선한다.** 그림의 창·기둥·장식 반복이 표와 다르더라도 놀이물 개수와 이동 경로를 바꾸지 않는다. 렌더는 실제 Unity 화면이나 완성된 프리팹이 아니다.

## 1. 만들 단위와 정보의 우선순위

만들 것은 **구역 공통 공간 3벌 + 게임별 교체 소품 10벌**이다. 같은 구역의 다른 미니게임이 뽑혀도 북벽·창·바닥·아치의 건축 언어는 유지한다. C 해자, B 아래층, J 수조처럼 바닥을 바꾸는 게임은 바닥 삽입 부품도 게임별 킷에 포함한다.

| 구분 | 적용 방식 |
|---|---|
| 기존 규칙·수량 | 사용자 원문과 현재 Core·미니게임 코드가 기준. 이미지 때문에 바꾸지 않음 |
| R310·R311 3D 연결 규격 | 원래 초반의 이음매를 중반·후반에 맞춘 기획 제안. 중반·후반 Unity 확정 치수로 취급하지 않음 |
| 이 문서의 새 모듈·재질·LOD | 모델링 시작을 위한 **제안치**. 사용자가 확정하거나 Unity에서 검토한 결과가 아님 |
| 컨셉 이미지 | 전체 인상·건축 형태·표면·장치의 구조를 읽는 자료. 치수 도면·물리 시험 결과가 아님 |

그림은 큰 인게임 예상 전경과 장치·재질 참고를 함께 보여 준다. 실제 제작 전에는 해당 게임의 평면 배치와 장치 축을 별도로 맞춘다. 특히 A의 공유판, C의 전체 폭 해자, B의 남겨 둔 가운데 통로를 보통의 두 팀 소품 배치로 치환하지 않는다.

3D에서는 모든 구역의 **게임 소품**을 끌 수 있고, **주변 장식 숨김은 초반에서만 제공**한다. 초반에서 두 표시를 끄면 건축 껍데기와 교체 킷의 구분을 읽기 쉽다. A는 공유판 중앙 단면, 다른 게임은 백 스테이션 중심 단면을 기준으로 읽는다.

## 2. 공간의 자와 연결

좌표는 Unity 기준 **+z가 북쪽·진행 방향, +y가 위**, 미터 단위다. 그림의 카메라 방향과 무관하다. 미니게임 스테이션의 로컬 u는 북쪽, v는 가로이며 3D 예시에서는 `world z = u + 4`로 연결한다.

| 항목 | 기준 | 모델링에서 지킬 점 |
|---|---|---|
| 폰 | 키 약 1m | 장치 높이·막대·문턱을 폰과 나란히 비교. 사람 크기 실내 가구로 키우지 않기 |
| 입구 | (0,0,0) | 양쪽 경계 석재·바닥 무늬를 정확히 이어 붙이는 기준 |
| 전체 폭 | 44m | 팀 스테이션 중심 x−12·+12. 외벽 두께와 돌출 장식은 플레이 폭을 먹지 않게 바깥으로 |
| 앞길 | z0~4 | 팀으로 갈라지는 자리. 장식 소품·가구로 입구를 좁히지 않기 |
| 두 스테이션 | 각 20×20m, z4~24 | 가운데 폭4m 길. A와 C의 예외는 각 게임 절 참조 |
| 놀이 단 | 바닥 위 +0.4m | 코스 바닥보다 어둡고 무광. 입구 램프, 깃발, 간판이 단과 할 일을 구분 |
| 입구 띠 | 스테이션 u0~2.5 | 승격 발판·진입 공간. 장치 장식이 침범하지 않게 유지(A 시작은 기존 u2 예외) |
| 북벽 구역 | z24~30 | 중앙 닫힌 큰 문 + 좌우 팀 문. 벽은 평면 배경이 아니라 문틀 깊이·상부 구조가 있는 건축 |
| 문 뒤 회랑 | z30~36 | 좌우 문에서 가운데 공통 출구로 합류. 그림의 문 뒤에도 실제 이동 공간을 남기기 |
| 공통 출구 | (0,0,36) | 출구 높이0 유지. 이번 디자인 때문에 왕실 층 계단을 추가하지 않기 |
| 진입 테라스 | 폭12×깊이6m, +1m | 앞 장애물 프리팹 소유. 마지막 강한 장치와 미니게임을 안전하게 분리 |
| 열린 진입 아치 | 안쪽 폭12m, 높이5m 이상 | 미니게임 북쪽 중앙문과 다른 문. 여닫는 장애물을 넣지 않음 |
| 내려가는 계단 | 0.25m×4단 | 보이는 단과 걷는 충돌면은 별개 제작. 래그돌 발이 단에 걸리지 않는지는 후속 Unity 확인 |

후반 장애물·결승 공간은 이번 작업에서 설계하지 않는다. 미니게임 뒤쪽 그림은 연결 방향만 제안하며 슬롯7 결승 방의 확정안으로 쓰지 않는다. 앞 장애물 장소별 소품도 대표 예시이고 해당 프리팹의 실제 복제본이 아니다.

## 3. 세 구역 공통 건축 킷

### 초반 — 왕궁 정문 앞 바깥뜰

크림 석회암을 **각진 큰 블록**으로 쌓고 모서리만 짧게 다듬는다. 왕궁 정면 파사드의 중앙 정문이 가장 큰 덩어리이며, 좌우 작은 팀 문은 멀리서도 출구로 읽혀야 한다. 룩 모양 문루·둥근 창·벽체 기단·세로 벽기둥으로 정면을 나누되, 실루엣이 장난감 체스 성처럼 단순해야 한다.

밝은 크림 포장 위의 어두운 놀이판과 참나무 장치가 초점이다. 벽 위는 크림·금 깃발과 회색 슬레이트를 쓰고, 가장자리에는 낮은 잔디·사이프러스·돌 화분·돌 벤치를 둔다. 맑은 낮, 짧고 부드러운 그림자, 물의 청록 반사가 기본이다. 초반 전체를 지붕으로 덮지 않는다. D의 누각은 부분 처마·목재 지지보로만 차이를 준다.

| 건축 부품 | 조형·표면 | 역할·주의 |
|---|---|---|
| 석회암 벽·기단 | 큰 엇갈림 줄눈, 넓은 무광면, 작은 모서리 깨짐 | 낡은 폐허로 만들지 않음. 올라갈 수 있는 장치처럼 작은 돌출턱을 연속 배치하지 않기 |
| 정문·팀 문 틀 | 묵직한 돌 아치·참나무 문짝·짙은 철물 | 중앙문은 닫힘, 두 팀 문이 실제 통과 경로 |
| 룩 문루·코니스 | 사각 덩어리와 톱니, 짧은 회색 지붕 | 파랑 지붕은 백팀 소유 표시처럼 보이므로 피하기 |
| 정원 가장자리 | 낮은 돌 화분·돌 벤치·삼각형에 가까운 사이프러스 | 플레이판·1m 주변 이동 공간에는 들어오지 않음 |
| 천·문장 | 크림 깃발, 무광 금 왕관 | 팀 진척 깃발을 제외한 장식에는 팀색 금지 |

### 중반 — 아랫궁의 작업·생활 홀

크림 대리석 벽 아래에 짙은 호두나무 판벽 허리를 둔다. 높은 창이 공간을 가로로 비추고, 상부 발코니와 벽등·샹들리에가 실내 깊이를 만든다. 정면 중앙에는 6랭크 왕실 날개 문장, 좌우 팀 문에는 진척 표시를 분리한다. 바닥은 밝은 크림·회색 체크 대리석, 놀이 단은 짙은 청회색이다.

기본 3D 천장 높이는 약13m 제안이며 E의9m 책장 꼭대기에 폰·열람등·카메라 여유가 필요하다. 천장 보·샹들리에가 등반 꼭대기를 관통하지 않게 별도 단면에서 확인한다. 건축 금은 어둡고 무광, 할 일 금은 작고 밝게 유지한다.

| 건축 부품 | 조형·표면 | 역할·주의 |
|---|---|---|
| 판벽 모듈 | 큰 직사각 패널, 깊지 않은 프레임, 바닥 걸레받이 | 낮은 벽에서는 폰과 게임 물체의 윤곽을 분리 |
| 대리석 상벽·창 | 굵은 창틀, 넓은 벽면, 단순한 석재 띠 | 빛나는 세로 금 띠가 할 일처럼 보이지 않게 |
| 2층 발코니 | 두꺼운 슬래브·규칙적인 난간 | 새 지름길로 쓰지 않는 배경. 실제 통과 가능 여부는 그림만으로 정하지 않음 |
| 샹들리에·벽등 | 큰 원형 프레임, 촛불 묶음, 벽 연결 브래킷 | E 진행 표시와 일반 조명은 재질·제어를 분리할 수 있게 구성 |
| 북벽 팀 문 인서트 | B 천막·E 회전책장·F 거울·J 수문옆문 | 문틀은 공유하되 게임별 열리는 부품을 별도 제작 |

### 후반 — 알현실 앞의 왕실 홀

중반보다 높은 대리석 기둥과 천창, 큰 왕관을 단8랭크 정문으로 위계를 올린다. 기본 3D의 약17m 천장은 제안치다. 높은 곳은 보라·크림 깃발과 흰 기물 문장, 묶은 벨벳으로 채운다. 낮은 플레이 영역은 조용하고 단순하게 비워 남색 그림자 속에서도 킹·가마·방패가 분리되게 한다.

크림 대리석 바닥 가운데 보라 러너를 두되, H의 체스판과 둘레1m에는 깔지 않는다. I의 빛줄기 높이에서는 벨벳·황동 장식선을 멀리 둔다. G의 담비털은 느린 칸에만 존재해야 한다.

| 건축 부품 | 조형·표면 | 역할·주의 |
|---|---|---|
| 대리석 기둥·기단 | 굵은 수직 덩어리, 작은 무광 황동 기둥머리 | 기둥 장식이 체스판 기능성 기둥과 혼동되지 않게 바깥 배치 |
| 왕관 정문 | 가장 큰 문틀, 남색 문짝, 상부 왕관 | 중앙 정문은 상징물. 플레이 동선은 좌우 팀 문 |
| 천창·상부 장막 | 긴 창과 정돈된 천 접힘 | 시선 유도용 빛을 플레이 위험 표시와 구분 |
| 보라 러너·깃발 | 넓고 단순한 색면, 흰 기물 문장 | 작은 황금 무늬를 과하게 반복하지 않음 |
| 벽감·수납 | 가마 차고, 기물 상자, 커튼 뒤 공간 | 실제 장치의 대기·출현 위치를 숨길 수 있는 깊이를 확보하는 제안 |

## 4. 색·재질과 장식 밀도

| 재질 역할 | 색·질감 방향 | 분리할 이유 |

| 바깥 석회암 | 크림, 큰 면, 거친 무광 | 배경 건축. 놀이 단과 명도 대비 |

| 메이플·호두나무 | 따뜻한 밝은 나무 / 짙은 갈색, 읽히는 결 방향 | 기능성 장치의 큰 실루엣과 이동축을 강조 |

| 장식 황동 | 더 어둡고 채도 낮은 무광 황동 | 놀이 단 둘레2m에서는 기능성 금과 확실히 차이 |
| 팀 표시 | 하늘색 #3FC1D9 / 주황 #F08A2C 계열의 제안 | 깃발·진척·칠한 칸 테두리·잡은 물체 외곽선에 한정. 캐릭터 팀색 변경 확정 아님 |
| 위험 | 빨강 #E0483B 계열 | 체크 고리·예고만. 장식 천이나 팀 구분에 쓰지 않음 |
| 천·벨벳 | 크림·보라·남색, 큰 접힘 | 작은 천 시뮬레이션을 요구하지 않는 고정 형상 제안 |
| 물·거품 | 청록 해자 / 연한 비눗물, 얇은 수면 | 수면이 보이게 유지. 거품·수련은 주변부 위주 |

표의 색은 제작 팔레트 출발점이다. 실제 조명·톤 매핑에서 다르게 보일 수 있으므로 Unity에서 같은 장면에 놓고 결정한다. 밝기값이나 폴리곤 수를 성능·가독성 검증 결과로 표현하지 않는다.

## 5. 게임별 킷과 상세 장면

수량은 **별도 표시가 없으면 한 팀 스테이션 기준**이다. 한 광장 전체 수량은 대부분 두 배다. 장식 개수는 제안이며 게임 규칙 수량과 구분한다.

### C · 해자 도개교 — 초반

[컨셉 이미지](ConceptArt/R311/01_early_C_moat.png)

- **장식 세트:** 받침대 위 큰 체스 시계, 예비 기물 상자, 기보 석판. **판 위와 판 둘레1m에 보라 러너를 깔지 않는다.**
- **구조:** 기둥은 큰 단순 충돌 형태, 장식 머리는 별도 메시로 제안한다. 킹의 변색·금 효과와 눕는 회전을 독립 제어할 수 있게 한다. 기물 상자는 배경 장식과 잡힌 목표를 담는 자리의 역할을 구분한다.
- **그림에서 읽을 것:** 남아 있는 킹과 굳어 잡을 수 있는 킹, 기둥을 피해 움직이는 빈 칸. 다른 종류 기물로 판을 가득 채운 장면이 아니다.

## 7. 메시·충돌·동적 축의 분리

공간을 한 덩어리로 합쳐 생성하거나 전체 방을 하나의 복잡한 충돌 메시로 쓰지 않는다. 다음 구분은 모델링 파일의 컬렉션·오브젝트 구분 제안이며 새 Unity 태그나 컴포넌트를 추가한 상태가 아니다.

## 8. 재질 슬롯·LOD·내보내기 제안

- **재질 슬롯:** 석재/목재/철/장식 황동/기능성 금/팀 표시/꺼진 등/켜진 등/천/물·유리를 역할별로 분리한다. 같은 색이라는 이유로 체크 경고와 팀 재질을 합치지 않는다. 문 진척·팀 깃발·열람등처럼 게임에서 제어할 면은 독립 교체가 가능해야 한다.
- **표면 디테일:** 멀리서 읽을 실루엣과 큰 베벨을 먼저 모델링한다. 책 글자·작은 못·돌 미세 균열·나뭇결은 텍스처·노멀로 처리할 수 있는 제안이다. 바닥 줄눈은 실제 깊은 홈을 파지 않아도 된다.
- **LOD:** LOD0은 가까운 장치·단면, LOD1은 중간 거리, LOD2는 큰 실루엣 위주로 제안한다. 초기 감소 비율은 약100/45/15%를 출발점으로 삼되 성능 보장치가 아니다. 작은 못·책 반복·사슬 고리는 먼저 단순화한다. 금 손잡이·체크 고리·목표등·팀 표시 같은 규칙 단서는 먼 거리에서도 갑자기 사라지면 안 된다.
- **충돌:** 벽은 상자, 드럼은 단순 원통, 상판·방패는 상자 등 큰 형태로 제안한다. 시각 LOD와 판정 충돌체를 함께 켰다 끄지 않는다. 장식 비계·벽 책장·발코니의 등반 가능 여부는 별도 Unity 설정과 플레이 확인이 필요하다.
- **폴리곤 예산:** 이미지에서 적정 폴리곤 수·프레임을 추정하지 않는다. 공통 킷을 조립한 뒤 목표 PC·실제12명 환경에서 성능을 재고 예산을 확정한다. 이번 산출물에는 그러한 성능 측정이 없다.
- **내보내기:** 미터 단위·일관된 축·바닥 기준점·적용된 스케일을 유지한다. 메시 이름은 영어로 예: `PR_Early_Wall_4m_LOD0`, `PR_C_BridgeDeck`, `PR_E_ShelfTower_9m`. 기존 프로젝트의 임포트 방식과 재질 경로를 대조한 뒤 적용한다.

## 9. 제작 순서와 확인할 장면

1. 초반 C·중반 E·후반 G를 대표로 잡고 공통 건축3벌의 큰 덩어리만 조립한다.
2. 폰1m 기준 인형을 넣고 입구·팀 문·뒤 회랑·장치 높이·카메라 가림을 맞춘다. 장식 전 상태에서 공간을 읽을 수 있어야 한다.
3. 각 게임의 수량·축·기능성 금을 넣고 시작/중간/완료 상태를 만든다. A는 공유판, C는 전체 폭 물, B는 중앙 통로를 별도 확인한다.
4. 나머지7종 소품을 같은 껍데기에 교체해 넣는다. 배경 재질은 공유하고 게임의 고유 실루엣을 우선한다.
5. 입구 안쪽3~4개 소품·상부 건축·천·조명을 넣는다. 팀색·금·빨강의 의미가 유지되는지 다시 본다.
6. 후속 Unity 작업에서 이동·등반·잡기·충돌·문 열림·온라인·성능을 확인한다. 이번 컨셉·3D가 그 확인을 대신하지 않는다.

| 확인 시점 | 볼 항목 |
|---|---|
| 안전 테라스·입구 | 할 일과 팀 문을 처음 보았을 때 읽는지, 열린 진입 아치와 닫힌 중앙문을 혼동하는지 |
| 전체·위에서 | 게임 수량·경로·가운데 동선·문 뒤 합류·배경 소품 밀도 |
| 스테이션 단면 | C 수면·B 아래층 깊이·E 쉬는 턱과 꼭대기 여유·J 통 높이·I 빛줄기 높이 |
| 폰 가까이 | 잡는 면·막대 높이·판자 끝·레일·문턱·통 가장자리의 읽힘 |
| 시작/중간/완료 | 움직임 공간이 장식을 관통하지 않는지, 진행 상태와 출구 변화가 연결되는지 |

R311의 산출물은 **이미지·3D·제작 제안**이었다. R312에서는 공통 건축3벌과10종 외형을 기존 `Mg*` 게임에 연결한 실제 프리팹을 저장했다. 모듈 치수·조명·가구 디테일·팀색은 사용자 확인 전이며, 구간 조합 코스의 Steam 연결·실제12명 성능은 별도 작업이다.

R312 수정은 `MiniGamePalaceArt`의 건축·소품 빌더에 반영한 뒤 **ChessFight → Pawn Rush → Build All Mini-game Prefabs**로 다시 굽는다. 정적 건축은 저장하지만 Play 시작에는 `Game socket`의 기능 게임과 장식을 재설치한다. 따라서 소켓 내부의 수동 편집은 Play에서 유지되지 않고, **Build All**은 정적 건축도 다시 만든다. 별도 시험 씬은 **Open Mini-game Prefab Test**로 연다([상세](PAWN_RUSH_MINIGAME_SECTIONS.md)).

AI의 실제 Unity 로드·팀별 문 연결·초기화 자동검사는 통과했다. **사용자 Unity·Steam 확인과10종 장치 직접 입력·퍼즐 완주는 아직 전**이다. 자동 완료 이벤트 검사로 손맛이나 실제 해결 가능성을 확인한 것으로 취급하지 않는다.
