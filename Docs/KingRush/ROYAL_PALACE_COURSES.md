# 윗궁 코스 프리팹 5개 (R115)

2026-10-31. 사용자 첨부 `manifest_v2_phase3.json`과 장소별 설계 기준에 따른 **편집 가능한 프로토타입**이다. 범위는 사용자가 확인한 윗궁 5개. 최종 모델링/텍스처나 완성된 6v6 밸런스가 아니다.

## Unity에서 실행

1. `ChessFight → Courses → Open Royal Palace Test` 또는 `Assets/Scenes/RoyalPalaceCourseTest.unity`를 연다.
2. Play. 기존 `RagdollPawn`과 `RagdollTuning`을 그대로 사용한다.
3. `[` / `]` 또는 Tab 메뉴로 5개 코스를 바꾼다. 한 번에 선택한 코스 하나만 물리를 실행한다.
4. R은 마지막 체크포인트, F3은 현재 코스 처음부터. 낙사하면 자동 복귀한다. 주행 시간·낙사·체크포인트를 HUD에서 확인한다. 메뉴를 열어도 시간은 흐른다.
5. 이동 WASD, 점프 Space, 질주 Shift, 좌클릭 태클, 우클릭 잡기. 이 시험 씬은 **오프라인 1인**이며 Steam/로비나 12인 봇 연결은 포함하지 않는다.

씬에는 첫 번째 코스가 **실제 프리팹 인스턴스**로 저장되어 있다. 나머지는 Project에서 각 프리팹을 더블클릭하여 편집한다. 실행 중 바꾼 값은 저장되지 않으므로 영구 수정은 Stop 후 Prefab Mode에서 한다.

[저장된 기하를 읽어 만든 상면 배치도](ROYAL_PALACE_LAYOUT.svg). Unity 캡처나 컨셉아트가 아닌 실제 저장 배치의 도식이다.

## 편집 구조

- 루트 `CourseModule`: ID·이름·입구/출구·체크포인트·경로·배치 영역·목표 시간.
- `Beats`: 구간 01~06. 이름 앞 번호가 기존 장애물 번호다. 각 장치의 전용 컴포넌트에서 속도·거리·밀치기·높이·위상 등을 변경한다. 일반 공통 수치를 Context로 옮기지 않았다.
- `Connectors and checkpoints`: 입구와 경로 표식. 끝 경계/홀에 속하는 표식은 그 구조 아래에 있다.
- `Boundary`: 마지막 장치 이후 힘이 없는 18m 진입로, 12×6m 체크포인트 테라스, 열린 아치, 묶인 보라 커튼, 0.25m씩 네 계단과 연속 보행 경사 충돌면.
- `Transition hall`: 44×25m 바닥·고정 연결 구조. 중앙 닫힌 문은 장식이며 양쪽 열린 출구에서 합류한다.
- `MinigameSlot`: 20×20m 팀 영역 2개와 중앙 4m의 **교체용 표시**. 이 자식의 내용만 바꾸면 입출구/경로 참조는 유지된다. 실제 미니게임/승패/문 잠금 로직은 없다. 기존 대형 ChessTimer 씬을 이 크기에 자동 축소·삽입하지 않는다.

프리팹을 씬에 드래그하여 수정한 뒤 루트 또는 자식을 선택하고 `ChessFight → Courses → Save Selected Course As Prefab`으로 별도 변형을 저장할 수 있다. 루트 위치/회전은 초기화하여 저장한다. 내부 장치의 변경·배치는 유지된다.

`CourseModule` Inspector의 `Previous exit`에 이전 코스 출구를 지정하면 입구를 맞출 수 있다. 루트 스케일은 1, 회전은 Y축만 사용한다. **연결점 정렬은 코스 전체의 겹침을 해결하지 않는다.** 선택 Gizmo의 배치 영역과 실제 경로를 확인하고 연결 통로/배치를 조정해야 한다. 자동 무작위 3장애물+2미니게임 조립기는 이번 작업 범위가 아니다.

## 설계 수치와 현재 코드의 차이

- 폭 12m, 72m 길이의 구간 6개를 왕복 회랑으로 연결. 양쪽에는 낙사 공간이 있고 끝 연결로만 다음 구간에 진입한다. 체크포인트는 2/4구간 이후와 마지막 테라스에 있다.
- 저장 경로 표식 길이는 약 **644.6m**(미니게임 홀의 한쪽 출구 경유 포함). 현재 튜닝 이동 5.5m/s 기준 약117초 + 장애물 지연65초 + 재시도40초 + 경계15초 ≈237초를 출발점으로 삼았다. 질주9.6m/s·등반·실제 인원/밀치기에 따라 크게 달라지므로 **240초 고정 타이머가 아니다**. HUD 측정은 입구부터 홀 뒤 합류 출구까지며 미니게임 플레이 시간은 포함하지 않는다.
- 첨부의 점프 발판 `Forward Speed`는 현재 코드에 없는 과거 필드다. 현재 `Jump Height=4.1m`(중력9.81에서 초기 상향 속도 약9m/s), `Air Move Speed=6`, `Air Acceleration=12`를 사용한다. 방향키로 착지 방향을 조절한다.
- 실제 원형 탁자는 14m/18°/s. 소용돌이는 같은 운반 규칙을 쓰되 시각 메시만 정지한다. `Diameter`를 바꾸면 Geometry Root의 메시/충돌 크기가 함께 바뀐다.
- #12 기존 `FoldingBridge`는 하중으로 아래로 접히는 장애물이다. 새 `RoyalDrawbridgeLeaf : ObstacleMotion`은 닫힘5초→열림2초→유지2초→닫힘2초, 최대65°의 **상향 시간형 변형**이다. 기존 하중/접이식 다리 로직은 유지했다.
- 모든 시간형 장치는 기존 `ObstacleClock`을 사용한다. 하중 다리/스프링/붕괴 같은 상태형 장치는 배제했다. 이것이 온라인 연결 완료를 뜻하지는 않는다. 공유 시각에서 `ObstacleContext.Authority`와 호스트 충격 판정을 연결하는 작업은 별도다.
- 지도·주화·망토·천문 구체는 구분을 위한 단순 조형이다. 첨부 이미지 생성 프롬프트/Windows 이미지 경로는 실행하지 않았으며, 최종 미술 제작이 남아 있다.

## 생성/검사

원본: `Tools/RoyalPalace/design.json`(최신 매니페스트의 기획 필드만 보관), `build_courses.py`(명시적 배치).

```bash
python3 Tools/RoyalPalace/build_courses.py --check
python3 -m unittest discover -s Tests/Gameplay -p 'test_royal_palace_courses.py' -v
```

`--write`는 새 파일이 없을 때만 작성한다. **`--overwrite`는 Unity에서 수정한 이 5개 프리팹·해당 재질·시험 씬을 덮어쓴다.** 평소 편집에는 실행하지 않는다. 기존 `gen_scenes.py`는 실행하지 않고 순수 YAML 직렬화 정의만 재사용한다. 배치도 갱신은 `preview_layout.py`(Python matplotlib/PyYAML 필요).

자동 검사는 GUID/fileID·부모/자식 연결, 단위 스케일/입출구/3체크포인트/경로 길이, 운반 장치 아래 고정 우회 바닥, 점프 발판 착지 가능 수치, 나이트/캐슬링 참조와 기본 간격을 검사한다. **Unity import, Editor 메뉴, PhysX 주행, 카메라, 우회/등반 난이도, 6v6 충돌/성능은 미확인**이다. 검증 목록은 [VALIDATION](../Network/VALIDATION.md) R115를 따른다.
