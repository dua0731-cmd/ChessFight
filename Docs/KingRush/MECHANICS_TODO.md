- **무엇·왜**
- **지금 코드**(근거 파일)
- **어디에**(어셈블리 경계)
- **네트워크**
- **완료 기준**

읽기 전에 루트 [HANDOFF.md](../../HANDOFF.md) §4 절대 규칙을 읽는다. 특히 이 여섯 가지를 지킨다.
- 장애물의 자세는 `ObstacleClock` 시간의 **순수 함수**다. 프레임마다 더하지 않는다.
- 클라이언트는 **입력만** 보낸다.
- `Assets/Scripts`는 래그돌 타입을 모른다. 래그돌은 Steam을 모른다. 캐릭터는 `ICharacterDriver`와 `Gameplay/Characters`의 인터페이스로만 부른다.
- 물리 콜백 안에서 순간이동하거나 관절을 부수지 않는다. 알리기만 하고 다음 Update에서 처리한다.
- 네트워크 형식을 바꾸면 `SteamSession.Protocol` 또는 래그돌 프로토콜 번호를 올린다.
- 사용자가 Unity나 Steam에서 **직접 본 것만** "성공"으로 기록한다.

> 이 문서의 파랑 미션과 빨강 코스는 **1차 안**이다(DESIGN 머리말). 먼저 만들 것은 **능력(K3)** 과 **한 판의 뼈대(K0·K1·K5)** 다. 미션 부품(K6~K8)은 뼈대 위에서 하나씩 시험하며 만든다.

## 2. 새로 필요한 것 — 우선순위 순

P0 = 이것 없이는 한 판을 시험할 수 없음. P1 = 능력과 미션. P2 = 온라인과 나중 일.

### P0 — 한 판의 뼈대

**K0. 규칙 코어 `KingRushRules` + 경기 진행 `KingRushMatch`**
- **무엇·왜:** 누가 어느 구간에 있는지, 문이 언제 열리는지, 발판을 누가 가졌는지, 결승이 언제 시작하고 누가 이겼는지. 이것을 한곳에서 판정해야 방장이 결정하고 모두에게 보낼 수 있다.
- **지금 코드:** `QueenHillRules`/`QueenHillMatch`가 같은 모양이다(순수 규칙 + MonoBehaviour 껍데기).
- **만들 것 — `Core/KingRushRules.cs`** (Unity 없음, 시간은 공유 시계 초)

  | 판정 | 내용 |
  |---|---|
  | 구간 | Red1, Blue1, Red2, Blue2, Red3, Final |
  | 파랑 완료 | 팀별 완료 시각. 그 팀 **문 열림 시각 = min(자기 완료, 먼저 끝난 시각 + 20초)** |
  | 발판 | 발판 번호 → 차지한 캐릭터·팀. 한 번만 |
  | 파랑 1 | 팀별 잡은 수(다리 칸), 연장(2:00부터 10초마다 +1) |
  | 파랑 2 | 팀별 나간 인원, 연장 단계 |
  | 결승 | 킹 도착 시각 → **T0 = min(두 킹 도착, 첫 킹 + 25초)**, 팀별 게이지(초, 줄지 않음, 140초 뒤 2배), 붕괴 단계 = f(지금 − T0), 초읽기에 킹이 떨어지면 패배, 180초 판정 |
  | 전송 | `Encode()`/`Apply()`: 한 번 정해진 것(완료, 발판, T0, 승리)은 되돌리지 않는다. 형식이 틀리면 통째로 버린다 |

- **만들 것 — `Gameplay/KingRush/KingRushMatch.cs`**
  - 규칙을 들고 있다.
  - 캐릭터별 현재 구간을 추적한다(`SectionZone` 트리거).
  - 부활 위치: 빨강은 체크포인트, 파랑은 입구, 결승은 재진입.
  - 팀 문(`TeamGate`)을 열고 닫는다.
- **어디에:** 규칙은 `Core`(`ChessFight.Network` 네임스페이스, `ChessPieces`와 같다). 나머지는 `Gameplay`.
- **네트워크:** 방장만 판정한다. 나머지는 `ApplyRemote`한다(QotH M8과 같다). 게이지처럼 계속 변하는 값의 전송 방법은 K11.
- **완료 기준:** Unity 없는 테스트(`Tests/`)가 전부 통과한다.
  - 문 시각: 백 60초 완료 → 흑 문 80초. 흑이 70초에 끝내면 70초.
  - 발판 하나에 한 명.
  - T0 두 경우(둘 다 도착 / 25초 경과).
  - 게이지가 8초에 100%, 줄지 않음, 140초 뒤 2배.
  - 초읽기에 킹이 떨어지면 패배, 180초 판정.
  - `Encode`→`Apply` 왕복, 깨진 문자열 무시.

**K1. 킹 러쉬 기물표 (몸은 모두 폰)**
- **무엇·왜:** 킹 러쉬에서는 기물마다 몸이 같다(DESIGN UK11, §5.1). 킹도 무게·속도 보정과 면역이 없다.
- **지금 코드:** `ChessPieces.Stats(kind)`는 QotH 표 하나뿐이다(킹 3배 무게·0.8배 속도·전력질주 없음·면역, 룩 1.5, 나이트 0.8, 퀸 2). `RagdollPawn.SetPiece`가 이 표를 몸에 적용한다(밀림 1/무게, 이동, 등반, 전력질주, 면역).
- **만들 것:**
  - 표를 모드별로 고를 수 있게 한다. 예: `enum PieceTable { QueenHill, KingRush }`와 `ChessPieces.Stats(kind, table)`.
  - 킹 러쉬 표는 전부 1배, 전력질주 허용, 면역 없음이다.
  - 래그돌이 어느 표를 쓸지 받는 방법은 둘 중 하나로 한다(둘 다 규칙 13을 지킨다).
    - 모드가 경기 시작에 정적 값으로 설정한다(`ObstacleClock`처럼, 씬 로드 때 초기화).
    - `IPromotable`에 표를 넘긴다.
- **어디에:** `Core/ChessPieces.cs`, `RagdollPawn.Piece.cs`.
- **네트워크:** 기물 종류는 이미 스냅샷에 있다(M11). 표는 모드로 정해지므로 보내지 않는다.
- **완료 기준:**
  - 테스트: 킹 러쉬 표의 여섯 기물이 전부 (1, 1, 1, 전력질주, 면역 없음)이다.
  - 랩: 킹 러쉬 표에서 킹이 폰과 같은 속도로 달리고 같은 거리로 밀린다.
  - QotH 표는 그대로다.

**K5. 킹 러쉬 승격 발판 `KingRushPad` + 되돌리는 문**
- **무엇·왜:** DESIGN §5.2.
- **지금 코드:** `PromotionPad`는 F를 눌러 승격한다(`IInteractable`). `ChessPieces.CanPromote`는 **퀸을 막고 킹 승격을 허용**한다. 둘 다 QotH 규칙이라 킹 러쉬와 반대다.
- **만들 것:**
  - `KingRushPad`: 트리거 위에 **폰이 딱 한 명**일 때 1.5초 게이지가 찬다. 두 명 이상이면 멈추고, 내려가면 0이 된다. 킹과 승격한 사람은 세지 않는다.
  - 다 차면 `IPromotable.Promote(piece)`를 부르고 규칙에 "발판 n = 이 사람"을 기록한다. 그 뒤 꺼진다.
  - 위에 기물 홀로그램을 띄운다. 크게, 멀리서 보이게 한다.
  - 킹 러쉬 승격 규칙: 폰 → 룩·비숍·나이트·**퀸**. 킹은 안 된다. 경기 시작에 팀마다 킹 1명을 지정한다.
  - `PawnGate`: 파랑 출구 문을 지나면 `Promote(Pawn)`으로 되돌린다.
- **어디에:** `Gameplay/KingRush/`, 규칙은 `Core`.
- **네트워크:** 게이지는 방장이 판정하고, 결과만 규칙 `Encode`로 보낸다.
- **완료 기준(랩 시험대):**
  - 폰 하나가 1.5초 서 있으면 승격된다.
  - 폰 둘이면 멈춘다. 한 명이 내려가면 이어서 찬다.
  - 킹은 무시된다.
  - 승격 뒤 발판이 꺼진다.
  - 출구 문을 지나면 폰으로 돌아간다.
  - 물에 빠져 부활해도 기물이 유지된다.

### P1 — 능력

**K2. 능력 약속과 능력 구역**
- **무엇·왜:** 능력은 파랑에서만 켜진다(UK13). 쿨타임 고리는 모두에게 보인다. 퀸은 **E를 누르고 있기**가 필요하다.
- **지금 코드:** `CharacterCommand.Ability`는 누른 순간 신호만 있다. 능력 켜기·끄기와 쿨타임을 알려 줄 약속이 없다.
- **만들 것 (`Gameplay/Characters`)**
  - `CharacterCommand.AbilityHeld`(누르고 있는 동안, `ShoveHeld`와 같은 방식).
  - `IAbilityUser`: `bool AbilitiesEnabled { get; set; }`, `float Cooldown01 { get; }`, `bool AbilityActive { get; }`.
  - `IStatusReceiver.Levitate(float seconds, float height)`(승천, M13 가족).
  - `AbilityZone`: 파랑 경기장을 덮는 트리거. 들어오면 켜고, 나가면 끄고 쓰던 능력을 끝낸다.
  - 머리 위 쿨타임 고리 표시(`Gameplay` 쪽 보기 부품. `IAbilityUser`만 읽는다).
- **어디에:** 약속과 구역은 `Gameplay`. 구현은 래그돌(`RagdollDriver`가 전달한다).
- **네트워크:** 입력 패킷에 `AbilityHeld` 1비트를 넣고 프로토콜을 올린다(규칙 9).
- **완료 기준:**
  - 구역 밖 E는 아무 일도 하지 않는다(자물쇠 표시).
  - 구역 안에서는 쓴다.
  - 쓰는 중에 구역을 나가면 끝난다.
  - 고리가 쿨타임을 정확히 보여 준다(0→1).

**K3. 능력 6개 (래그돌)** — 숫자는 DESIGN §6 시작값. `RagdollPawn.Ability.cs` 부분 클래스로 만든다(`.Hook`, `.Piece`처럼). **쉬운 것부터** 만든다.

ChessFight 저장소에서 '킹 러쉬' 게임모드를 개발해 줘.

먼저 읽을 것:
1. 루트 HANDOFF.md 전체 (특히 §4 절대 규칙: 장애물은 ObstacleClock 시간의 순수 함수,

2. Docs/KingRush/DESIGN.md (킹 러쉬 1차 기획안 — 확정 UK1~UK16, 능력 §6, 미션 §8)

(JY-lobby에서는 캐릭터 조작·물리를 바꾸지 않기로 했다. 제안은 JY-ragdoll_v2에서 새 브랜치.)

- 기획안에서 '확정'(UK)은 바꾸지 말고, 바꿔야 하면 먼저 물어볼 것.

- 작업마다 Tools/run-tests-linux.sh --compile, Unity에서 확인할 순서를 알려 줄 것.
- 내가 Unity에서 본 것만 '성공'으로 기록, HANDOFF §8대로 문서 갱신.
