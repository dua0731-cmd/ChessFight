# 폰 러시 · 중반·후반 미니게임 3D 미리보기

2026-11-05 · R310 · **기획 검토용 3D 예시 / Unity 프리팹 구현 아님 / 사용자 확인 전**

사용자 요청: Claude Code의 **「폰 러시 미니게임 레벨 디자인」** 세션에서 초반 미니게임 프리팹 3D 미리보기를 확인하고 중반·후반도 만들기. 해당 세션의 최신 사용자 지시는 **"3D로 충분해"**였다. 원래 세션 문맥을 복제한 Claude Code 검토에서 중반 B·E·F·J, 후반 G·H·I의 핵심 장면과 연결 규격, 스테이션 단면의 필요성을 확인한 뒤 GPT가 페이지를 작성했다.

## 1. 열어 보기

- **[중반 4종 미리보기](PAWN_RUSH_MID_MINIGAMES_3D.html)**: 기본 E 왕궁 서고, B 보수 중인 동관, F 대무도회장, J 왕궁 세탁장.
- **[후반 3종 미리보기](PAWN_RUSH_LATE_MINIGAMES_3D.html)**: 기본 G 왕의 행차 회랑, H 국왕 체스 홀, I 국왕 침실.
- **[초반 기존 3D 예시](PAWN_RUSH_EARLY_PLAZA_3D.html)**: 원래 `claude/bold-johnson-8ez95n`의 `1ebc9cb0`에 있던 R155 예시를 이 문서들과 함께 열 수 있도록 복사했다. 원래 작업 폴더의 파일·프리팹은 수정하지 않았다.

HTML 파일을 Chrome 등 일반 브라우저에서 연다. 각 중반·후반 파일은 스타일·동작 코드가 포함되어 있어 파일 하나를 옮겨도 볼 수 있다. Three.js r128과 OrbitControls를 CDN에서 불러오므로 인터넷 연결과 WebGL이 필요하다.

## 2. 공통 공간과 조작

입구는 (0,0,0), 폭 44 m, 앞길 z 0~4, 팀 스테이션 x ±12·z 4~24, 북벽 z 24~30, 문 뒤 회랑 z 30~36, 출구는 (0,0,36)이다. 원문의 44 × 25 m 광장에 대해 초반 R154에서 적용한 앞길·문 뒤 회랑 규격을 중반·후반에도 맞추는 **시각 제안**이다. 중반·후반 Unity 자산의 확정 치수가 아니다.

| 조작 | 보여 주는 것 |
|---|---|
| 게임 전환 | 같은 껍데기 안의 중반 4종 또는 후반 3종 |
| 앞 장애물 끝 | 중반 2-1~2-5, 후반 3-1~3-5의 대표 소품과 공통 이음매 |
| 전체 배치·테라스·위에서 | 전체 구조, 입구 아치 너머 첫인상, 두 스테이션과 문 뒤 연결 |
| **스테이션 단면** | **x=−12**에서 백 스테이션을 자름. 책장 높이, B 아래층, J 수조, I 빛줄기 높이를 보기 위한 시점 |
| 걸어 들어가기 | 마지막 구간 → 테라스 +1 m → 0.25 m씩 4단 → 입구 띠 → 앞길 → 백 스테이션 |
| 동작 예시 재생·슬라이더 | 게임의 대표 동작과 완료 뒤 팀 문이 열리는 연출. 실제 물리나 플레이 시간의 시뮬레이션은 아님 |
| 백팀·흑팀·양팀 | 고른 팀의 동작만 진행. 문도 그 팀 것만 열림 |
| 천장·프리팹 경계·이름표 | 실내 인상, 두 프리팹의 소유 영역, 공간 이름 |

가운데 정문은 닫힌 채이고, 두 팀은 각자 옆문 → 뒤 회랑 → 공통 출구로 간다. 중반은 호두나무 판벽·체크 대리석·2층 발코니·6랭크 정문, 후반은 높은 대리석 벽·보라 러너·천창 인상·8랭크 알현실 정문이다. 천장은 기본 꺼져 있어 안이 보인다. 위험은 빨강, 팀 표시는 파랑·주황, 할 일은 금색으로 구분했다. 팀색은 기존 초반 예시를 이어 쓰는 제안이며 캐릭터 팀색 확정으로 취급하지 않는다.

## 3. 일곱 장면

| 게임 | 반영한 규칙·자리 | 대표 동작과 읽을 지점 |
|---|---|---|
| B · 보수 중인 동관 | 팀마다 10 m 낭떠러지, 판자 2열 × 5줄, 양쪽 판자 더미 | 아래층 비계 위로 마루를 메움. **스테이션만 끊고 가운데 통로는 유지** |

| F · 대무도회장 | 팀마다 태엽 폰 16개, 1.1 m 세 칸 레인 | 두 칸 스텝·금 고리. 거울은 3 m 위, 낮은 벽은 판벽 |
| J · 왕궁 세탁장 | `KnightRoute`의 d1·b2·a4·c5·e4·g5·h7·f8, 8칸, 6종 인형 | 빨래통의 방향 없는 점프대와 한 길. 점프 곡선은 시각 예시이며 도약 가능성 측정값이 아님 |
| G · 왕의 행차 회랑 | `KingEscortPath` 15칸, b4·b5·d6·e6 느린 칸, c6·f7 막은 룩 | 가마·룩 자체 이동 → 마지막 캐슬링. 작은 손잡이 블록·밧줄 없음 |
| H · 국왕 체스 홀 | 팀마다 8 × 8 판, c6·f3·f7 기둥, 상대 킹 6개 | 킹 이동·굳은 돌·빛기둥·기권처럼 눕기. 판 위에는 보라 러너 없음 |

코드 근거는 기존 `MgPlanks`, `MgBells`, Core `KnightRoute`·`KingEscortPath`와 [구역 배치 기획서 v0.1](PAWN_RUSH_MINIGAME_ZONES_v0.1.md)이다. 게임별 가구 위치·장식·카메라·연출 시간은 이번 예시를 위한 제안이다.

## 4. 클로드 검토를 반영한 경계

- x=0 단면은 통로만 잘라 탑·수조가 안 보인다는 지적을 반영해 **x=−12 단면**을 넣었다.
- 중반 뒤는 후반 장애물 방향, 후반 뒤는 슬롯 7 결승 방향만 표시했다. 아직 설계하지 않은 결승 방을 새로 확정하지 않았다.
- 후반 3-x 테라스 소품은 원문의 미정 사항이다. 페이지의 소품은 대표 예시이고 실제 장애물 프리팹의 복제본이 아니다.
- 출구 높이는 0으로 유지한다. "왕실 층으로 오르는" 계단을 미니게임 회랑 안에 임의로 넣지 않았다.
- 원래 초반 C의 사용자 Unity 확인을 이 일곱 예시의 확인으로 확대하지 않는다. `main`에 초반 C 프리팹을 병합하는 작업도 하지 않았다.

## 5. 파일과 검사

공용 원본은 `PAWN_RUSH_MINIGAME_PREVIEW.js`·`.css`다. 수정 뒤 `node Tools/Generators/build_minigame_previews.mjs`로 두 HTML을 다시 만든다. 초반 예시와 원문 사본의 출처는 원래 작업 폴더 `claude/bold-johnson-8ez95n`, 마지막 관련 커밋 `1ebc9cb0`이다. 원문 첫 줄은 이 사본의 초반 3D 예시로 연결했다. 초반 HTML 사본은 빠진 평면 도면 링크를 이 안내로 바꾸고 바닥글에 출처·Unity 미병합을 명시했으며, 3D 장면은 그대로다.

- 실제 Three.js r128 객체로 일곱 게임의 시작·완료·다섯 시점을 구성하여 **장면·카메라 49건**의 좌표 유한성·장면 생성 검사 통과. 그 안에서 **팀 문 소유권 7건**도 확인했다.
- 같은 장면을 CPU로 그린 서고·행차 회랑·세탁장 정지 그림으로 공간 배치를 AI가 확인했다. 브라우저 화면 캡처가 아니다.
- **브라우저 직접 조작은 미확인:** 앱 브라우저의 로컬 페이지 접근 제한으로 3D 화면·마우스 조작·모바일 화면은 직접 확인하지 못했다. 이 제한을 우회하지 않았다.
- Unity·Steam은 실행하지 않았으며 게임 코드·씬·프리팹 변경은 없다. 기존 Core·모의 세션 시험 결과는 HANDOFF와 REQUIREMENTS에 기록한다.

사용자가 볼 항목은 서고의 문 가림, B 아래층 깊이, 세탁장 도약 길의 읽힘, G 모퉁이, H 판 위 대비, I 빛줄기 높이, 앞·뒤 구간의 연결 인상이다. 이번 시각 제안을 확정한 뒤 필요한 게임의 Unity 프리팹 구현 범위를 따로 정한다.
