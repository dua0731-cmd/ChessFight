# 폰러시 구역 제작 작업환경 (R49)

2026-10-09. 대상 프로젝트 `C:/Users/Admin/Documents/GitHub/ChessFight`, 작업 씬 `Assets/Scenes/ImportedChessFightMap.unity`. JY-ragdoll_v2 로컬 적용, 커밋·푸시 없음. 오프라인 제작·시험 기반이며 온라인 경기 연결은 후속 작업이다.

## 바로 사용하기

1. Unity 상단 **ChessFight → Pawn Rush → 작업환경 열기**. Hierarchy의 **Pawn Rush Workspace**를 선택한다.
2. Inspector의 **현재 시드로 미리보기 조합** 또는 **새 무작위 조합 미리보기**로 구역을 확인한다. 편집은 씬 저장으로 보존하고 조합 교체는 Undo/Redo가 된다.
3. Play 시 기본값은 **매번 새 무작위 조합**. **저장된 미리보기**는 화면에서 보고 있던 배치를, **고정 시드로 조합**은 지정한 시드를 사용한다. 현재 조합 시드와 선택한 구역 ID는 Inspector에 표시된다.
4. **고정 배치** 배열은 순서대로 A1/A2/B1/B2/C1/C2다. 지정한 프리팹은 고정하고 빈 칸만 추첨한다. 같은 구역의 중복 배치는 거부한다.
5. **A2 구역부터 테스트** 같은 버튼으로 시작 구역을 바꿀 수 있다. 이때 자동으로 저장된 미리보기 모드가 된다. 처음으로 돌아가려면 **출발점에서 테스트 시작**을 누른다.
6. Play → Game 화면 클릭 → 기존 R48 래그돌 조작을 그대로 사용한다. WASD/Shift/Space, 마우스 시점·휠, 좌클릭 다이빙, 우클릭 잡기·등반, E 갈고리, **F 미션 봉인 활성화**, R 시작점 복귀.

씬이 이미 열려 있으면 디스크의 새 씬을 다시 열어 확인한다. 이후 작업은 이 핵심 프로젝트에서 진행한다. 원본 맵 프로젝트의 같은 이름 파일과 혼동하지 않는다.

## 씬 구성

```text
ImportedChessFightMap
├─ 기존 Map 및 배치 오브젝트들 (보존)
├─ Core Playtest (기존 LabGame/조작/튜닝 유지, 시작 위치만 새 코스)
└─ Pawn Rush Workspace (X=80, Y=0, Z=0)
   ├─ Course Entrance
   ├─ Start / Playtest Spawn
   ├─ Generated Sections
   │  ├─ A1 — 장애물
   │  ├─ A2 — 미션협동
   │  ├─ B1 — 장애물
   │  ├─ B2 — 미션협동
   │  ├─ C1 — 장애물
   │  └─ C2 — 미션협동
   └─ Finish
```

기존 Map은 지우거나 이동하지 않았고 오른쪽에 제작용 코스를 추가했다. 시작·도착 발판 사이에 6개 구역이 입구/출구를 맞춰 연결된다. 현재 예제는 폭 20m, 전체 구역 길이 268m다. 이것은 제작 규격의 시작값이며 5분 플레이타임이나 최종 난도 검증 결과가 아니다.

## 새 구역 만들기

1. Templates 또는 기존 구역 프리팹을 복제하고 Sections/Obstacles 또는 Sections/Missions에 저장한다.
2. 루트의 **PawnRushSection → Section Id**를 고유한 값으로 바꾸고 Kind를 지정한다. 동일 ID 두 개는 등록할 수 없다.
3. Prefab Mode에서 Geometry/Obstacles/Mission Content를 편집한다. 기존 장애물 프리팹은 Obstacles 아래에 배치한다.
4. **Entrance / Exit**는 루트 직계 자식이다. 둘 다 바닥 높이, 같은 X/Y, 로컬 회전 (0,0,0)으로 +Z를 향하게 한다. Exit.z는 Entrance.z보다 4m 이상 앞이다. 루트 Scale은 (1,1,1). 길이를 늘리면 바닥·출구·Authoring Bounds·문 위치도 함께 조정한다.
5. 입구와 출구의 보행 가능한 바닥 폭/높이를 맞추고, 움직이는 장애물의 이동 범위가 이웃 구역으로 넘지 않게 여유를 둔다. 직선 연결 규격만 자동 검사하며 모든 이동 범위와 우회 가능성을 대신 검증하지 않는다.
6. Catalog의 해당 목록에 프리팹을 등록하고 Workspace의 **배치·연결 검사**를 누른다. 슬롯을 고정하고 그 구역부터 테스트한다.

**Generated Sections는 조합 결과**다. 재조합하면 이 하위의 직접 편집은 교체된다. 지속할 디자인 변경은 구역 프리팹에서 한다. 미리보기에서는 Prefab 연결을 유지한다. 잘못된 목록/중복/유형 설정은 기존 배치를 지우기 전에 오류로 알린다.

## 미션과 팀별 문

- 기존 **ITeamMember/Teams(백·흑)**, **IInteractable(F)**, **TeamBodies**를 사용한다. 플레이어와 입력 시스템은 추가·교체하지 않는다.
- `TeamMission.objectiveIds`가 필요한 목표 목록이다. 팀마다 진척도를 따로 보관하고 같은 목표는 팀당 한 번만 인정한다. 전체 완료 시 `onTeamCompleted(int team)`이 한 번 발생한다.
- `MissionObjective`는 예제용 F 상호작용이다. 각 봉인은 두 팀이 각자 활성화할 수 있고, 표시등 두 개가 팀별 달성을 보여 준다. 현재 예제는 혼자도 완료 가능하며 인원 수를 강제하는 최종 협동 규칙은 아니다.
- 새 미션은 조건을 만족했을 때 `TeamMission.CompleteObjective(team, objectiveId)`에 보고하도록 연결한다. 키 수집·운반·발판 동시 점유 등의 구체적 판정은 해당 미션 프리팹에서 구현한다.
- `MissionTeamGate`의 백/흑 문은 자기 팀의 미션 완료 시 시각적으로 올라간다. 실제 차단 Collider는 유지하고 **완료한 해당 팀의 모든 래그돌 충돌체만** 통과시킨다. 상대 문은 이용할 수 없다. 팀 변경/문 비활성화/미션 초기화 때 통과 설정을 복구한다.
- 새 경기 조합 때 구역 인스턴스와 팀별 진척도를 초기화한다. 미션간 상태는 공유하지 않는다.

## 유지한 것과 후속 연결

- R48 LabGame/LabCamera/플레이어/튜닝과 기존 게임·승리·입력·패키지·ProjectSettings는 유지했다. 씬에서 테스트 시작점 좌표만 변경했다. 기존 씬의 저장된 오브젝트도 제거하지 않았다.
- 이번에는 **워크스페이스와 예제**를 구축했다. 전체 게임 룰·왕좌 승리·새 체크포인트 규칙·진행 UI·12인 온라인 전송은 구현 범위에 포함하지 않는다. R/낙사는 현재 테스트 시작점으로 복귀한다.
- 온라인 공유 시계/NetworkDriven 상태에서는 임의 추첨과 로컬 미션 판정을 차단한다. 현재 저장 배치 표시만 가능하며 완성된 온라인 관문이 아니다. 후속 작업에서 호스트가 선택한 `SelectionIds()`와 시드, 팀별 미션 상태를 모든 참가자에게 전달하고 권한·늦은 입장을 연결해야 한다. 네트워크 프로토콜은 바꾸지 않았다.
- 고정 시드 재현은 동일한 Catalog/프리팹 ID 집합을 전제로 한다. 목록에 새 구역을 추가하면 같은 시드도 결과가 바뀔 수 있다.
- 벽 넘기·갈고리 등으로 미션을 건너뛰는 악용 방지, 12인 병목/성능, 이동 발판을 포함한 구역 간 충돌 범위, 전체 완주 시간은 후속 플레이테스트 대상이다.
